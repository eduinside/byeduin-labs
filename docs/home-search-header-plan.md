# 홈 검색창 헤더 이동 계획

> 작성: 2026-10-06 · 대상: `src/pages/index.astro` · 상위: [new-apps-2026-10.md](new-apps-2026-10.md)

## 1. 왜

지금은 로고 아래에 검색창이 한 줄을 따로 차지한다(`.home-toolbar`, `index.astro` 906~931행). 넓은 화면에서는 헤더 오른쪽이 비어 있다. 검색창을 그 자리로 옮기면 한 줄(약 70px)이 줄어 공지와 '최근 방문'이 첫 화면에 더 많이 들어온다.

## 2. 바꿀 것

### 마크업
- `<form class="app-search">`를 `<main>`의 `.home-toolbar`에서 `<header class="site-header">` 안, 로고 묶음 다음으로 옮긴다.
- `.site-header`는 이미 `display:flex; justify-content:space-between`이라 구조는 그대로 둔다.
- 모바일 카테고리 칩(`.cat-chips`)은 `<main>`의 `.home-toolbar`에 남긴다. 검색창이 빠지면 데스크톱에서 `.home-toolbar`가 비므로 빈 여백이 생기지 않게 정리한다.
- `id`·`name="q"`·`aria-*`·`/` 단축키 안내는 그대로 둔다. 스크립트는 `#appSearch`·`#appSearchForm`을 id로 찾으므로 고칠 곳이 없는지 확인만 한다.

### 스타일
| 화면 폭 | 배치 |
|---|---|
| 768px 이상 | 한 줄: 왼쪽 로고, 오른쪽 검색창. 검색창 폭 `clamp(260px, 34vw, 420px)`, 세로 가운데 정렬 |
| 768px 미만 | 두 줄: 로고, 그 아래 전체 폭 검색창(지금 모바일 모양 그대로) |

- 헤더 아래 여백(`padding: 2rem 1.5rem 1rem`)은 유지하고, `.home-toolbar`의 `margin-bottom`은 칩이 있을 때만 남긴다.
- 높이 48px, 글자 16px(iOS 확대 방지)은 그대로.

### 선택(기본 끔)
- 스크롤하면 헤더 검색창이 위에 붙어 있는 모양(sticky)은 이번에 넣지 않는다. `/` 단축키가 있고, 화면 위쪽 떠 있는 버튼과 겹칠 위험이 있다.

## 3. 확인할 것

- [x] 1280px·1024px·768px·767px·375px에서 줄바꿈과 겹침이 없다(로고 부제 "바이브 코딩으로 만든 작은 앱 모음"이 검색창에 눌려 두 줄이 되지 않는지)
- [x] `/` 키로 검색창 이동, Esc로 지우기, `?q=` 주소로 들어오면 검색어가 채워지고 결과가 걸러진다
- [x] 검색 중 공지·최근 방문 숨김(`body.is-searching`), 결과 없음 안내가 그대로 동작한다
- [x] Tab 순서: 로고 → 검색창 → 공지 → 카테고리 — 운영에서 확인: 검색창 → 테마 → 공유 → 공지 → 전체 공지 → 카테고리(로고는 링크가 아니라 건너뜀)
- [x] 라이트·다크 대비, 포커스 링 — 버튼은 2px 테두리, 검색창은 파란 테두리·그림자
- [x] 우상단에 떠 있는 버튼(있는 경우)과 겹치지 않는다
- [x] `npm run build` + `npm run smoke` 오류 0건
