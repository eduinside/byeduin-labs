## 2. 데이터 계약 (1단원 JSON을 그대로 쓴다)

`받아쓰기_결과_1단원/sentence-bank.json`을 **가공 없이** 앱 정적 자산으로 반입한다.

- 반입 위치(제안): `src/pages/apps/dictation/data/unit-2-1-01.json` (Astro `import`) 또는 `public/apps/dictation/data/` (fetch).
- 앱이 소비하는 필드: `unit`, `낱말|구절|문장[]` 각 항목의 `id`·`text`·`char_len`·`tags`·`difficulty`. `source`·`generation_note`는 **화면 비노출**(검수 로그 용도, CLAUDE.md 지침 유지).
- `level-profile.json`은 MVP 화면에서 직접 쓰지 않음(원문 통계·규칙 분포는 다단원 밸런싱용). MVP에선 참고 자료로만 리포지토리에 동봉.

### 앱 내부 정규화 타입(런타임)
```ts
type Item = {
  id: string;            // "W01" | "P05" | "S12"
  kind: '낱말'|'구절'|'문장';
  text: string;          // 정답 원문(문장부호 포함)
  charLen: number;       // 공백 포함·문장부호 제외 글자수
  tags: RuleTag[];       // ["연음화","경음화",...] | ["받침없음/규칙없음"]
  difficulty: '하'|'중'|'상';
};
type RuleTag = '연음화'|'경음화'|'비음화'|'격음화'|'겹받침_단순화'|'받침없음/규칙없음';
```
> 태그 어휘는 1단원 데이터에 등장한 5종 + "규칙없음"으로 **고정**. 이후 단원도 같은 태그 체계를 쓰므로(작업패턴 v2), 앱은 이 6종만 알면 된다.

## 3. 재검토 ① — 교사용 받아쓰기 텍스트 산출

**목표:** 교사가 "오늘 불러줄 급수표"를 몇 번의 선택으로 뽑는다.

### 출제 옵션 (모두 로컬, JSON 필터링)
- 단원: (MVP는 1단원 고정, 셀렉트는 두되 "2학년 1학기 1단원"만 활성 — 다단원 확장 슬롯)
- 유형: 낱말 / 구절 / 문장 (복수 선택 가능)
- 난이도: 하 / 중 / 상 (복수 선택)
- 문항 수: 기본 10 (조건 충족 풀에서 랜덤 추출, 부족하면 있는 만큼 + 경고)
- 순서: 셔플 / 원본 순서 · "다시 뽑기" 버튼

### 산출물 3종
1. **불러주기 목록(교사 화면 전용):** 번호 + 텍스트 + 태그 배지. 학생 노출 금지 구역(§4에서 재생 중 텍스트 숨김).
2. **A4 인쇄 급수표(`--print`):** 문항 리스트(정답 포함/미포함 토글). Pretendard·흑백 인쇄 최적.
3. **학생 답안지(인쇄):** 번호 칸만 있는 빈 양식(1~N번, 줄 간격 저학년용 넓게).

> v0.2의 "문장 은행 + AI 보충 생성"은 **미도입**. 1단원 40문항이 이미 은행이고, 부족하면 조건을 넓히라는 안내로 대체. AI 문장 생성은 다단원 데이터가 쌓인 뒤 검토.

## 4. 불러주기 (브라우저 TTS)

- `SpeechSynthesis` API, `lang=ko-KR`, 서버 비용 0. (CLAUDE.md·v0.2 F-02와 동일)
- 문항별 재생, 기본 **2~3회 반복**(설정), 속도 **0.7~1.0x** 슬라이더.
- **재생 중 문항 텍스트 비노출** — 번호와 진행바(3/10)만. 프로젝터/어깨너머 노출 대비(v0.2 F-02 유지).
- 교사가 "다음/이전/다시" 수동 제어 + 자동 진행(간격 설정) 둘 다 지원.

### ⚠️ 검수 포인트 (구현 전 반드시 확인)
브라우저 표준 TTS는 **음운 변동을 항상 표기대로가 아니라 발음대로** 읽는지 보장되지 않는다. 받아쓰기는 "발음을 듣고 표기를 복원"하는 활동이므로, 예컨대 `옷을`을 [오슬]로 읽어줘야 정상이다. → 구현 첫 단계에서 1단원 40문항을 실제 음성으로 들어보고, 규칙이 반영되지 않는 항목 목록을 만든다. 문제가 크면 (a) SSML/발음힌트 필드 추가 또는 (b) 교사 육성 녹음 대체 재생을 후속 과제로. **MVP는 표준 TTS로 출발하되 이 리스크를 문서화한 채 검증한다.**

## 5. 재검토 ② — 결과(오류) 분석

**이것이 MVP의 차별화 핵심.** OCR·DB 없이 태그만으로 "어느 규칙에서 무너지는가"를 보여준다.

### 5.1 답안 입력·채점 (MVP는 직접 입력만)
- 방식: **교사/학생이 문항별로 타이핑 입력**(v0.2 F-03 B). 사진 OCR(F-03 A)은 미도입.
- 채점: 정답 `text`와 입력을 **자모 단위 비교**.
  - 정규화 규칙: 문장부호 제거(데이터 `char_len`이 이미 문장부호 제외 기준) → 공백 정규화(옵션: 띄어쓰기 틀림 표시/관용 선택) → 자모 분해 diff.
  - 자모 분해는 로컬 유틸(`es-hangul` 또는 자체 함수). **API 호출 없음.**
  - 판정: 완전일치=정답 / 불일치=오답, 그리고 오답 문항의 **틀린 자모 위치**를 하이라이트.

### 5.2 규칙별 오류 집계 (태그 기반, 로컬)
오답 문항의 `tags`를 모아 규칙별로 집계한다.
```
규칙별 오답률 = (해당 태그가 붙은 오답 문항 수) / (해당 태그가 붙은 출제 문항 수)
```
- 산출: 규칙 × 오답률 막대/히트맵(연음화·경음화·비음화·격음화·겹받침_단순화).
- 난이도별 정답률, 유형별(낱말/구절/문장) 정답률도 함께.
- **회차 누적은 미도입**(1회차 단발 분석). 단, 결과를 localStorage에 회차로 append해 두어 후속 누적 대시보드의 데이터 토대는 만든다(스키마만 미래지향).

### 5.3 localStorage 스키마(미래 확장 대비 최소형)
```jsonc
// key: dictation:attempts
[{
  "at": "2026-07-14T10:00:00Z",
  "unit": "2-1-01",
  "items": [{ "id":"S12", "correct": false, "input":"저는 정하윤임니다", "wrongTags":["비음화"] }],
  "byRule": { "연음화": {"asked":5,"wrong":2}, "경음화": {"asked":3,"wrong":0} }
}]
```

## 6. 재검토 ③ — 추가 제안 (지도 방향)

오류 분석을 "그래서 뭘 하라"로 번역하는 층. **MVP는 규칙별 정적 템플릿**으로 충분하다.

### 6.1 규칙별 지도 문구 룩업 테이블(정적, 6종)
각 음운규칙에 대해 (교사용 한 줄 + 학부모용 존댓말 한 줄 + 예시 낱말) 고정 문구를 앱에 내장. 예:
- **연음화**: "받침이 뒤 글자로 넘어가 소리 나는 낱말을 어려워해요. `옷을[오슬]`처럼 또박또박 끊어 읽으며 받침을 확인해요."
- **경음화**: "된소리로 나지만 예사소리로 적는 낱말에서 틀려요. `학교[학꾜]`—소리와 표기가 다름을 짚어줘요."
- (비음화·격음화·겹받침_단순화 동일 형식으로 사전 작성)

→ 결과 화면에서 **오답률 상위 규칙 1~2개**의 문구를 자동 노출. 예시 낱말은 1단원 데이터에서 해당 태그 문항을 골라 채운다.

### 6.2 다음 회차 추천 문항
오답률 높은 규칙의 태그를 가진 문항을 1단원 풀에서 골라 "복습 급수표"로 재출제 버튼 제공(로컬 필터, AI 불요).

### 6.3 (선택·후순위) AI 지도 가이드
회차 누적·여러 규칙이 얽힐 때만 가치가 있으므로 **MVP 필수 아님**. 도입 시 `functions/api/dictation-guide.js`로 기존 `_ai.js`의 `generateContent()` 재사용(Gemini flash-lite), 입력은 §5.3의 `byRule` 요약. 키는 이미 설정됨. **MVP 체크리스트에는 넣지 않고 §9 로드맵에 둔다.**

## 7. 화면 흐름

```
[홈/출제] 단원·유형·난이도·문항수 선택 → 급수표 생성
   ├─(인쇄)→ A4 급수표 / 학생 답안지
   └─(진행)→ [불러주기] 큰 재생 버튼·번호·진행바(텍스트 숨김)
                 → [채점] 문항별 입력 그리드(정답 대조·자모 하이라이트)
                     → [결과] 점수 + 규칙별 오류 히트맵 + 지도 제안 + 복습 재출제
```
- 모드 토글: **교사 모드**(불러주기 제어·인쇄 중심) / **학생 모드**(스스로 듣고 입력·채점). 데이터·채점 로직 동일, 노출 UI만 차이.

## 9. MVP 범위 확정 & 로드맵 경계

### ✅ MVP (이 문서가 다루는 끝점 — 1단원 결과 파일로 동작)
- [ ] 1단원 JSON 반입 + 정규화 로더
- [ ] 출제 필터(유형·난이도·문항수·셔플) → 급수표 생성
- [ ] A4 급수표·학생 답안지 인쇄(`--print`)
- [ ] 브라우저 TTS 불러주기(반복·속도·텍스트 숨김) + **발음 반영 검수**
- [ ] 직접 입력 채점(자모 diff·문장부호/공백 정규화·오답 하이라이트)
- [ ] 규칙별 오류 집계 히트맵 + 난이도/유형별 정답률
- [ ] 규칙별 정적 지도 문구(6종) + 복습 재출제
- [ ] localStorage 회차 저장(누적 대시보드용 스키마 확정)
- [ ] apps.json 등록(edu/edu-learn·학습지원)

### ⛔ MVP 밖 (설계하지 않음 — 참고용 경계만)
- 나머지 15개 단원 데이터 생성(`받아쓰기_작업패턴.md` 파이프라인 반복)
- 사진 답안 OCR 채점(v0.2 F-03 A, Gemini Vision)
- D1(`ds_` 테이블)·R2·회차 누적 대시보드·학급 관리
