## 0. 검토 기준

각 아이디어를 4개 축으로 평가한다.

- **구현 난이도(Feasibility)**: 단일 HTML + Canvas/SVG/Web Audio + localStorage로 완결 가능한가. (별이 많을수록 쉬움)
- **교육 효과(Effectiveness)**: 머릿속으로 상상하기 어려운 개념을 "조작 → 즉시 변화"로 체득시키는가.
- **교육과정 적합성(Fit)**: 현행 초등 교과 단원과 직접 매칭되는가.
- **리스크**: 모델 튜닝 난이도, 스코프 확장 위험, 오개념 유발 가능성.

핵심 원칙: **모델이 단순해도 조작–반응 루프가 즉각적이면 효과가 크다.** 반대로 모델을 정교하게 만들수록(생태계·시장) 초등 수준에서 오히려 "왜 이렇게 되는지" 설명이 어려워져 효과가 떨어질 수 있다.

### 개별 코멘트

- **A 도형의 이동** — 아이들이 공간지각에서 가장 헷갈리는 단원인데, "버튼 누르면 애니메이션으로 돌아간다"가 곧 정답 확인이 된다. 외부 의존성 0, SVG/Canvas 변환행렬만으로 완결. volcano식 "자유조작 → 미션(예측 후 확인) → 결과"에 완벽히 맞는다. **가장 안전하고 효과 확실.**
- **B 태양 고도·그림자** — `moon-phase`와 한 세트가 되는 "천체·계절" 라인업. 남중고도라는 추상 개념을 슬라이더(위도·절기·시각)로 그림자 길이/기온이 실시간 변하는 2D 사이드뷰로 체감. 삼각함수 한 줄로 그림자 계산. 모델이 물리적으로 정확하면서도 설명 가능 → 오개념 위험 낮음.
- **C 확률·가능성** — 구현 난이도 최저(RNG + 막대 누적 애니메이션). "10번 vs 1000번"에서 비율이 이론값에 수렴하는 걸 눈으로 보는 순간이 강력. 다만 "대수의 법칙" 용어는 교육과정 밖 → "많이 할수록 가능성에 가까워져요"로 톤 조정.
- **D 양팔저울** — 드래그앤드롭으로 추를 걸면 토크(무게×거리)로 기울기 계산. 초등은 정량(모멘트)까지 안 가고 "규칙 발견"이 목표이므로 모델은 단순해도 됨. 손맛(hands-on)이 좋아 몰입도 높음. 모바일 드래그 처리만 신경.
- **E 용돈 관리** — Toss식 미니앱 UI. 돌발 이벤트 카드 → 잔액 실시간 변동 → 예산 초과 즉시 피드백. localStorage로 "이번 달 기록" 저장. 정답이 하나가 아닌 의사결정형이라 효과는 좋으나, "합리적 소비" 판정 로직을 가치중립적으로 짜는 설계가 관건.
- **F 리듬 메이커** — 창작+청각 피드백이 매력적. 단, Web Audio 스케줄링(정확한 박자 재생)·모바일 오디오 언락·음가 배치 UX가 다른 앱보다 손이 더 감. 효과는 좋지만 첫 타자로는 부담.
- **G 생태계** — 개념(먹이그물 연쇄)은 좋으나 Lotka-Volterra류는 파라미터에 민감해 쉽게 "전멸"하거나 발산 → 초등에겐 "왜?"가 설명 안 됨. **정교한 미분방정식 대신, 몇 개 시나리오(개구리↓ → 메뚜기↑ → 벼↓)를 단계 카드로 보여주는 "연쇄 스토리형"으로 재설계**하면 효과·안전 모두 확보.
- **H 도시 계획** — 심시티 라이트. 몰입·확장성 최고지만 시설 밸런스·타협조건 로직으로 스코프가 쉽게 커진다. **그리드 5×5, 시설 6종, 점수 3축으로 범위를 강하게 고정**해야 단일 HTML로 완결 가능.
- **I 수요·공급** — 경제 모델 튜닝이 어렵고, 잘못 만들면 "가격 올리면 무조건 이득" 같은 오개념을 심을 수 있음. 우선순위 낮춤. 만들면 H의 이벤트 카드 방식을 재활용.
- **J 세계 탐험대** — volcano(화산 탐험대)의 검증 스택(MapLibre + 위성타일 + 3D 지형 + `flyTo` 관광)을 **그대로 재사용**하는 자매 앱. 신규 기술 리스크 거의 0, 저학년(2학년 통합교과 「세계」) 커버리지를 처음 여는 앱. 유일한 주의점은 문화 콘텐츠의 고정관념·저작권 → 개발문서의 설계 대원칙으로 통제.
- **K 발명 아이디어 공작소** — "AI에게 답을 받는" 게 아니라 "AI가 **질문**해서 아이의 발상을 끌어내는" 코치형. SCAMPER를 저학년용 4카드(합치기·나누기·크기 바꾸기·재료 바꾸기)로 축소. 유일하게 서버(AI 프록시)가 필요한 앱이라 정적 SPA 원칙의 **명시적 예외** — 단, 무상태 프록시만 쓰고 DB는 없음(개발문서 §2). 효과는 라인업 중 최상급(창작+AI 협업 경험).

## 4. 최우선 상세 기획: A. 도형의 이동 시뮬레이터

### 4-1. 개요
- **앱 ID**: `shape-move` (`/apps/shape-move/`)
- **셸**: `immersive` (volcano와 동일, 전체화면 캔버스)
- **한 줄**: 모눈 위 도형을 밀기·뒤집기·돌리기 하며 "이동해도 모양·크기는 안 변한다"를 체득
- **교과**: 수학 4학년 「평면도형의 이동」
- **배지**: `시뮬레이션`

### 4-2. 화면 흐름 (volcano 패턴 이식)
1. **인트로** — 미션 카드("도형을 움직여도 모양과 크기는 그대로일까요?") + 시작 버튼
2. **자유 탐험** — 좌: 모눈 캔버스 / 우: 조작 사이드바
   - 도형 선택(삼각형·ㄴ자·사다리꼴 등 비대칭 도형 → 뒤집기·돌리기 차이가 드러나게)
   - 버튼: `← → ↑ ↓ 밀기` / `좌우 뒤집기` `상하 뒤집기` / `⟳ 90° 돌리기` `⟲ -90°`
   - 모든 변환은 **0.4s 애니메이션**으로 이동 궤적을 보여줌(순간이동 금지 — 궤적이 핵심)
   - "처음으로" 리셋
3. **미션(퀴즈)** — "이 도형을 오른쪽 그림처럼 만들려면?" 목표 도형(반투명 고스트)을 제시 → 아이가 변환 버튼으로 맞추기, 또는 "밀기/뒤집기/돌리기 중 무엇?" 예측 후 확인
4. **결과** — 맞힌 미션 수 + 배움 정리("밀기·뒤집기·돌리기 모두 모양과 크기는 변하지 않아요. 위치·방향만 바뀌어요.")

### 4-3. 기술 설계
- **렌더링**: SVG 권장(모눈 배경 + `<polygon>` + CSS `transform` 트랜지션으로 애니메이션 간단). 대안 Canvas.
- **상태**: `{ shapeId, x, y, flipX, flipY, rot }` — 변환은 상태 갱신 → transform 재계산.
- **뒤집기 vs 돌리기 구분**: 비대칭 도형이어야 교육 효과 발생(대칭 도형은 차이가 안 보임).
- **localStorage**: 완료한 미션·별점, "내가 만든 무늬(테셀레이션)" 저장 정도. 개인정보 없음.
- **공유**: 상태를 `btoa(encodeURIComponent(JSON))` 해시로 → `shareCurrentPage()`로 단축링크(공통 패턴). "내가 만든 도형 배치" 공유.
- **외부 의존성**: 없음(폰트만). volcano의 maplibre 같은 CDN도 불필요 → 오프라인·저사양에서도 안정.

### 4-4. 디자인
- 공통 3종(`hero-theme.css`·`app-shell.css`·`theme.js`) + `init.js`/`app-shell.js`/`seo-injector.js` 로드.

- 버튼은 `.fd-btn` 계열 + 큰 아이콘 버튼(저학년 터치 타깃 ≥44px).

### 4-5. 확장(후속)
