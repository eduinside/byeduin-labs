# idea-lab — 발명 아이디어 공작소 개발문서

> 작성: 2026-07-04 · 작성자: Claude Fable 5 · 상위 기획: [simulation-apps-plan.md](simulation-apps-plan.md) (저학년 통합교과 라인)
> 제약: 정적 SPA + **무상태 AI 프록시 1개**(상위 문서 "서버 없음" 원칙의 명시적 예외, §2) · DB 없음 · 저장은 localStorage만
> 컨셉: AI가 답을 주는 도구가 아니라 **AI가 질문하는 코치**. 아이가 고른 물건 × 발상 카드에 대해 AI가 저학년 눈높이 질문을 던지고, 아이의 대답을 모아 발명 카드를 완성한다.

---

## 1. 개요

| 항목 | 값 |
|------|-----|
| 앱 ID | `idea-lab` (`/apps/idea-lab/`) |
| 이름 · 이모지 | 발명 아이디어 공작소 · 💡 |
| 셸 | `column` (단계형 카드 흐름 — 지도/캔버스형 아님) |
| 카테고리 | `edu` / `edu-sim` · 배지 `AI` (기존 AI 앱 배지 관행 확인 후 통일) |
| 한 줄 | 합치기·나누기·크기·재료 바꾸기 4가지 발명 마법으로 나만의 발명품을 구상하고, AI 코치와 다듬어 이름 짓고 그림까지 완성 |
| 교과 | 1~2학년군 통합교과 「탐험」(발명·궁리) — 2학년 적용 |
| 대상 | 초등 저학년 · 태블릿/크롬북 |

### 교육 논리
발명 교육의 고전 기법 SCAMPER(대체·결합·응용·변형·용도변경·제거·재배열)는 저학년에게 과다 → 4가지로 축소한 **"발명 마법 카드"**: ① 합치기(결합) ② 나누기·빼기(분해) ③ 크기 바꾸기 ④ 재료 바꾸기. 기존 발명 사례에서 "이 발명은 어떤 마법을 썼을까?"를 먼저 발견하게 한 뒤, 같은 마법을 자기 물건에 적용한다(사례 → 전이 구조).

> ⚠️ 조사 한계: 「탐험」 단원의 발명 관련 차시명·성취기준 코드는 웹 조사 불가로 미대조 → 구현 전 교과서 확인(검수 체크리스트 포함).

### 학습 목표
1. 발명은 "없던 것을 만드는 마법"이 아니라 **있는 것을 바꾸는 궁리**임을 안다.
2. 합치기·나누기·크기 바꾸기·재료 바꾸기 4가지 발상법을 사례에서 발견하고 직접 적용한다.
3. 자기 아이디어를 말로 설명하고, 이름 짓고, 그림으로 표현하는 창작 경험.

## 2. 제약 예외 선언 (상위 문서 헤더 원칙의 명시적 예외)

- 시뮬레이션 라인업 대원칙("순수 정적 SPA·서버 없음")의 **첫 예외 앱**. 단, 예외 범위를 최소화한다:
  - **무상태(stateless) AI 프록시만 신설** — `functions/api/idea-lab.js`. 프로젝트 기존 관행([_ai.js](../functions/api/_ai.js)를 쓰는 signage·flash-recommend·bu-recommend)과 동일 구조.
  - **DB·세션·업로드 없음**. 아이의 작품 저장은 전부 `localStorage`. 서버는 "질문 생성기·그림 생성기"일 뿐 아무것도 기억하지 않는다.
- AI 엔진(모두 기존 `_ai.js` 재사용, 신규 키 불필요):
  - 텍스트: `generateContent` — 기본 flash-lite(가장 저렴·빠름, 기존 호출부와 동일 기본값). 코치 질문은 짧아서 충분.
  - 이미지: `generateImage` — Timely 경유 `gemini-2.5-flash-image`(폴백 gemini flash image preview). **"퀄리티보다 속도" 요구에 정확히 부합하는 기존 파이프라인**(signage-image에서 검증됨).

## 3. 화면 흐름

```
[인트로] → [1. 발명의 비밀 탐험(사례)] → [2. 내 발명 만들기(물건×마법카드)]
        → [3. AI 코치와 궁리(질문 2~3개)] → [4. 이름 짓기] → [5. 그림 그리기(AI)]
        → [발명 카드 완성 → 내 작품집]
```

1. **인트로** — "발명가는 마법사예요! 4가지 발명 마법을 배우고 나만의 발명품을 만들어요."
2. **발명의 비밀 탐험** — 실존 발명 사례 카드 6~8개를 뒤집으며 "어떤 마법을 썼을까?" 4지선다(마법 카드 매칭):

   | 사례 | 마법 |
   |------|------|
   | 지우개 달린 연필 | 합치기 |
   | 바퀴 달린 여행가방 | 합치기 |
   | 접는 우산 | 크기 바꾸기 |
   | 씨 없는 수박 | 나누기·빼기 |
   | 종이 빨대 | 재료 바꾸기 |
   | 미니 선풍기(손풍기) | 크기 바꾸기 |

   - 정적 콘텐츠(AI 불필요). 사례의 사실관계는 구현 시 재검증.
3. **내 발명 만들기** — ① 물건 고르기: 그림 팔레트(우산·가방·필통·컵·신발·의자 등 16개 이모지 그리드) **+ 직접 쓰기**(≤20자). ② 마법 카드 1~2장 선택. ③ (합치기면) 두 번째 물건 선택.
4. **AI 코치와 궁리** — 서버가 질문 2~3개를 순차 제시. 예: "☂️우산과 🎒가방을 합치면 **언제** 좋을까요?" → 아이는 **선택지 3개 + 직접 쓰기**로 답변(타이핑 부담 최소화 — 선택지도 AI가 함께 생성). 마지막에 AI가 아이 답을 모아 **아이디어 정리문 2~3문장** 생성("비 오는 날 손이 자유로운 '우산 가방'! ...").
5. **이름 짓기** — AI 후보 3개 + 직접 입력. 아이가 최종 선택(아이의 결정권 보장).
6. **그림 그리기** — 서버 템플릿 프롬프트로 이미지 생성: "어린이 크레파스 그림 스타일, 단순한 형태, 흰 배경, {정리문 요약}". 생성 중 로딩 애니메이션(10~20초 대비). **실패/느림 시 fallback: 이모지 조합 카드**(물건+물건 이모지 크게)로도 발명 카드 완성 가능 — 이미지가 없어도 흐름이 죽지 않게.
7. **발명 카드 완성** — 이름·마법 카드·정리문·그림 한 장 카드. `내 작품집`(localStorage)에 저장, 여러 개 수집.

## 4. API 설계 — `functions/api/idea-lab.js`

```
POST /api/idea-lab   body: { action, ... }
  action: 'coach'  { item, item2?, magic, step, answers[] } → { question, choices[3] }
          'refine' { item, item2?, magic, answers[] }        → { summary }
          'name'   { summary }                                → { names[3] }
          'image'  { summary }                                → { b64 }
```
- 응답은 **JSON 강제 + 정규식 추출 파싱**(bu-recommend 검증 패턴). 파싱 실패 시 클라이언트가 재시도 1회 → 그래도 실패면 고정 질문 세트로 진행(AI 없이도 완주 가능한 **오프라인 질문 뱅크** 내장).
- 시스템 프롬프트 고정 지침: 초등 2학년 눈높이(짧은 문장·쉬운 낱말·존댓말), 안전(위험한 발명 유도 금지), 아이 답 존중(부정 평가 금지, "멋진 생각이에요" 톤), 질문은 1개씩.

## 5. 안전·남용 방지 (저학년 + 공개 AI 엔드포인트)

1. **입력 검열**: madang 검증 관행 재사용 — 로컬 금칙어 프리필터(즉시 차단) + OpenAI Moderation(타임아웃 시 통과, madang과 동일한 가용성 우선 정책). 대상: 아이가 직접 쓴 텍스트(물건 이름·답변·발명 이름)만.
2. **프롬프트 주입 축소**: 아이 입력은 시스템 프롬프트가 아닌 **서버 템플릿의 지정 슬롯**에만 삽입 + 길이 제한(물건 20자·답변 100자). 이미지 프롬프트는 스타일 부분 전체를 서버 고정(입력이 스타일 지시를 못 건드림).
3. **개인정보**: 입력창에 "내 이름·친구 이름은 쓰지 않아요" 안내 문구. 서버 무저장이므로 잔류 위험 없음.
4. **비용·남용**: flash-lite(텍스트)로 호출당 비용 최소화. 이미지는 **완성 단계 1회 + 재생성 2회 제한**(클라이언트) + 서버 입력 길이 검증. 공개 무게이트는 bu-recommend 관행과 동일 수준 — 남용 징후 시 Turnstile 후속 도입 검토(관련 스킬 보유).
5. **콘텐츠 안전**: 시스템 프롬프트에 무기·위험물 발명 회피 지침, 이미지 프롬프트에 안전 스타일 고정.

## 6. 저장·공유

- `localStorage` 키: `idea-lab:v1` → `{ works:[{ id, item, item2, magic, answers, summary, name, createdAt }], settings }`. **이미지 b64는 용량상 저장하지 않음**(localStorage ~5MB 한계) — 작품집에서는 이모지 카드로 표시하고 "그림 다시 그리기" 버튼 제공. (썸네일 축소 저장은 구현 중 용량 실측 후 결정.)
- 공유: `#share=` payload `{ v:1, item, item2, magic, summary, name }` — 받는 쪽은 카드 재구성 + 그림 재생성 버튼. `shareCurrentPage()` 단축링크.

## 7. 디자인

- 공통 3종(`hero-theme.css`·`app-shell.css`·`theme.js`) + 표준 스크립트, `column` 셸.

- 저학년 규격: 터치 타깃 ≥ 48px, 문장당 ≤ 25자, TTS 읽어주기 버튼(미지원 시 자동 숨김). madang v2의 저학년 모드 UX 경험 참고.
- 마법 카드 4종은 색+아이콘+이름 병용(합치기 🧲 / 나누기 ✂️ / 크기 🔍 / 재료 🧱).

## 8. 스코프 제한 (Non-goals)

- **자유 채팅 없음** — AI와의 상호작용은 구조화된 질문·선택지 흐름만(챗봇 아님, 저학년 안전·비용 통제).
- 작품 서버 저장·갤러리·타인 작품 열람 없음(DB 없음 원칙). 공유는 URL payload 1건씩만.
- 이미지 편집·재화질·스타일 선택 없음 — 고정 스타일 1종(크레파스풍), 속도 우선.
- 로그인·학급 관리 기능 없음.

## 9. 제작·배포 절차

1. 스캐폴드:
   ```bash
   node scripts/scaffold-app.js --id idea-lab --name "발명 아이디어 공작소" --base column \
     --category edu --subcategory edu-sim --emoji 💡 --desc "4가지 발명 마법과 AI 코치로 나만의 발명품을 구상하고 이름 짓고 그림까지 완성"
   ```
2. `functions/api/idea-lab.js` 신설(§4) — `_ai.js` import, 검열·길이 제한 포함.
3. `apps.json` 수동 보강: 배지(AI 관행 확인), SEO:
   - `seo.title`: `발명 아이디어 공작소 — 초등 저학년 AI 발명 발상 도구`
   - `seo.description`: `합치기·나누기·크기 바꾸기·재료 바꾸기 4가지 발명 마법으로 아이디어를 떠올리고, AI 코치의 질문으로 다듬어 이름 짓고 그림까지 완성하는 초등 저학년 창의 발명 학습 앱.`
   - `seo.keywords`: `발명 아이디어`, `아이디어 발상`, `초등 발명 교육`, `SCAMPER`, `창의력`, `AI 학습 도구`
4. 구현 → `npm run dev`(프록시는 `wrangler pages dev`로 로컬 확인) → `npm run inject` → `npm run og` → `npm run sitemap` → 커밋.

## 10. 검수 체크리스트
