# eco-web — 생태계 탐험대 개발문서

> 작성: 2026-07-03 · 작성자: Claude Fable 5 · 상위 기획: [simulation-apps-plan.md](simulation-apps-plan.md) §G (검토 후 "만들기 + 시나리오 연쇄형"으로 재설계 확정)
> 제약: 순수 정적 SPA(단일 HTML) · localStorage만 사용 · 외부 의존성 0(폰트 제외)
> 설계 대원칙: **자유 파라미터 개체군 동역학(Lotka-Volterra류) 금지.** 교육과정이 생태계 평형을 정성적으로만 다루므로, 정량 미분방정식은 교과 초과 + 오개념 유발. 대신 ①먹이그물 만들기 ②피라미드 쌓기 ③평형 시나리오 연쇄의 3모드로 구성.

## 1. 개요

| 항목 | 값 |
|------|-----|
| 앱 ID | `eco-web` (`/apps/eco-web/`) |
| 이름 · 이모지 | 생태계 탐험대 · 🌿 |
| 셸 | `immersive` (volcano 동일 — 관계도/드래그 캔버스가 뷰포트를 소유) |
| 카테고리 | `edu` / `edu-sim` · 배지 `시뮬레이션` |
| 한 줄 | 먹이그물을 직접 잇고, 피라미드를 쌓고, 한 생물이 사라지면 무슨 일이 생기는지 확인하는 생태계 종합 실험 |
| 교과 | 초등 5~6학년군 「생물과 환경」 |
| 대상 기기 | 교실 태블릿·크롬북 우선 (드래그 인터랙션 중심, 터치+마우스) |

### 교과 근거 (2022 개정, 5~6학년군 「생물과 환경」)
- 생태계 구성요소(생물요소/비생물요소) 구분
- 먹이사슬과 먹이그물, 먹고 먹히는 관계
- 생태피라미드(단계가 올라갈수록 수가 줄어듦)
- 생태계 평형: **어떤 생물의 수가 갑자기 변하면 다른 생물도 영향을 받고, 시간이 지나면 다시 평형을 회복한다** — 정성적 이해
- 비생물 요소(빛·물·온도)가 생물에 미치는 영향

### 학습 목표
1. 생물을 생산자/소비자(1·2·3차)/분해자로 분류하고, 먹고 먹히는 방향으로 연결한다.
2. 먹이그물이 먹이사슬 여러 개가 얽힌 구조임을 발견한다.
3. 상위 단계로 갈수록 개체 수가 줄어드는 피라미드 구조를 안다.
4. 한 생물의 증감이 연쇄적으로 다른 생물에 영향을 주고, 결국 평형으로 돌아옴을 이해한다.

### 오개념 교정 포인트
- **"화살표는 먹는 쪽을 가리킨다"** ↔ 교과 규약은 **먹히는 것 → 먹는 것**(에너지 이동 방향). 미션 판정에서 방향 오류를 즉시 교정 — 이 앱의 핵심 정확성 포인트.
- **"위(최상위 포식자)가 가장 많다"** → 피라미드 뒤집으면 무너지는 연출로 반증.
- **"천적이 사라지면 무조건 좋다"** → 메뚜기 폭증 → 벼 전멸 → 결국 메뚜기도 굶음의 연쇄로 반증.

## 2. 화면 흐름

```
[인트로] → [모드 허브] ─┬─ 모드1: 먹이그물 공방
                        ├─ 모드2: 피라미드 쌓기
                        └─ 모드3: 평형 시나리오
                              ↓
                        [배움 정리 / 결과]
```
3모드는 독립 진입 가능한 허브 구조(volcano의 단일 흐름과 달리, 종합 앱이라 허브형). 각 모드에 자유 탐험 + 미션이 들어감.

### 2-1. 인트로
- 미션 카드: "숲속 친구들은 어떻게 이어져 있을까요? 직접 이어 보고, 한 친구가 사라지면 어떻게 되는지 알아봐요." + `시작하기`.

### 2-2. 모드1 — 먹이그물 공방 (핵심 모드)
- **생물 카드 팔레트**(화면 하단/측면): 벼·풀·메뚜기·개구리·뱀·매·토끼·여우·다람쥐·버섯(분해자) 등 한 생태계(들·숲) 12종. 각 카드에 역할 색 태그(생산자=초록/1차=노랑/2차=주황/3차=빨강/분해자=회색).
- **조작**: 카드를 캔버스로 드래그 배치 → 두 생물을 잇는 화살표를 드래그로 생성(먹히는 것에서 시작해 먹는 것으로 놓기). 잘못된 방향/불가능한 관계(풀→매 직접 연결 등)는 연결 시도 시 흔들림 + 안내.
- **자유 탐험**: 자유롭게 이어 나만의 먹이그물 완성. 연결 개수·사슬 최장 길이 실시간 표시.
- **미션(먹이그물)**:
  | # | 유형 | 예 |
  |---|------|----|
  | ① 사슬 잇기 | "풀에서 시작하는 먹이사슬 하나를 완성하세요" | 풀→메뚜기→개구리→뱀 |
  | ② 그물 완성 | 제시된 그물에서 빠진 화살표 3개 채우기 | |
  | ③ 분류 | 각 생물을 생산자/소비자/분해자로 태그 분류 | |
- 판정: 그래프의 방향성 간선 집합 비교(정답 그물은 데이터로 정의). 여러 올바른 사슬을 모두 인정.

### 2-3. 모드2 — 피라미드 쌓기
- 모드1에서 만든(또는 예시) 먹이그물의 생물을 **영양 단계별 층**에 배치. 층이 올라갈수록 칸(개체 수)이 줄어드는 사다리꼴.
- **조작**: 생물 토큰을 맞는 층으로 드래그. 각 층의 상대적 개체 수를 막대/토큰 개수로 시각화(정량값 아님 — "훨씬 많다/적다"의 상대 표현).
- **오개념 연출**: 상위 층에 하위보다 많은 토큰을 쌓으면 피라미드가 기우뚱 흔들리며 "위가 더 많으면 먹이가 모자라요" 안내.
- **미션**: 뒤섞인 생물을 올바른 층으로 분류, "생산자는 왜 가장 많을까요?" 3지선다.

### 2-4. 모드3 — 평형 시나리오 (연쇄 스토리형, ODE 아님)
- **시나리오 카드** 3~4개 선택: "메뚜기가 갑자기 늘면?", "개구리가 사라지면?", "매가 이사 오면?", "가뭄이 들면?(비생물)".
- 선택 시 **단계 카드가 순차 재생**: 각 단계마다 관련 생물의 개체 수 아이콘이 늘거나(▲) 줄고(▼), 화살표로 다음 영향 대상을 지목. 예: 개구리▼ → (개구리가 먹던)메뚜기▲ → (메뚜기가 먹는)벼▼ → 먹이 줄어 메뚜기▼ → 개구리 회복 → **평형 복귀**.
- **정성 규칙만**: 각 단계 전이는 데이터로 하드코딩된 인과 경로(런타임 수치 시뮬 없음). "왜?"가 항상 한 문장으로 설명되도록 설계.
- 마지막 카드는 항상 "시간이 지나면 다시 균형을 찾아요"로 평형 회복을 명시.
- **미션**: "개구리가 사라지면 메뚜기 수는?" 예측(▲/▼/그대로) → 연쇄 재생으로 확인(예측→확인 원칙).

### 2-5. 결과 / 배움 정리
- 3모드 완료 배지 + 정리 카드: "생물들은 먹고 먹히며 그물처럼 이어져 있어요. 한 생물이 변하면 모두 영향을 받지만, 생태계는 스스로 **다시 균형**을 찾아요."
- `다시` / `모드 허브` / 공유(내가 만든 먹이그물).

## 3. 기술 설계

### 3-1. 렌더링 · 드래그
- **SVG** 확정: 생물 노드 `<g>`(이미지/이모지 + 라벨), 화살표는 `<line>`+`<marker>`(방향 표시), 피라미드는 `<polygon>` 층. 드래그·연결은 포인터 이벤트.
- 시나리오 연쇄 재생: 단계별 노드 상태(▲/▼/-) CSS 트랜지션 + 화살표 하이라이트 순차 점등.

> **재검토 보완 — 드래그 공유 방식**: 이 프로젝트는 앱마다 단독 `index.html`이고 `/common/`에 공유 드래그 로직이 없으므로, "D에서 만들어 재사용"은 그대로는 성립하지 않는다. **권장: `/common/drag-connect.js` 신설**(단자-스냅·간선 드로잉·포인터/터치 정규화 헬퍼)을 최초 도입 앱이 만들어 eco-web·circuit-lab·양팔저울이 공유. 세부는 [circuit-lab-plan.md](circuit-lab-plan.md) §3-3 참조.
> **접근성 대체 조작 필수**: 드래그 불가 사용자를 위해 "생물 탭 → 대상 생물 탭"의 2탭 연결 모드와 키보드 포커스 이동을 병행 제공.

### 3-2. 데이터 모델
```
생태계 정의(정적):
  species = [ { id, name, role, trophic, emoji } ]
  validEdges = [ [preyId, predatorId], ... ]        // 방향: 먹힘→먹음
  scenarios = [ { id, title, steps: [ { speciesId, delta, note, nextId } ] } ]

사용자 상태:
  build = { placed: [id...], edges: [ [a,b]... ] }   // 모드1 결과
  pyramid = { layerOf: { id: trophicLevel } }        // 모드2
  progress = { missions: {...} }
```
- 미션 판정: `edges`를 `validEdges`(또는 미션별 정답 부분집합)와 방향 포함 비교.

### 3-3. 저장 · 공유
- `localStorage` 키: `eco-web:v1` → `{ missions, build, settings }`.
- 공유: `#share=` payload `{ v: 1, build }` — "내가 만든 먹이그물" 공유. 수신 측은 그 그물을 로드한 공방으로 진입. `shareCurrentPage()` 단축링크(vives-share 규약). 진도 미포함.

### 3-4. 의존성
- 외부 CDN 0. 오프라인 완전 동작. 생물 그림은 이모지 또는 인라인 SVG(외부 이미지 요청 없음).

## 4. 디자인

- 공통 3종 + 표준 스크립트, `immersive` 셸(테마 토글 자동 숨김).
- 역할 색 체계(생산자/1·2·3차 소비자/분해자)를 `:root` 변수로 정의하고 **색+아이콘 병용**(색약 대비). 화살표 방향 마커는 크고 명확하게.
- 카드/토큰 터치 타깃 ≥ 44px. 드래그 시 스냅 가이드라인 표시.
- 다크모드에서 관계선·화살표·역할색 대비 확인.

## 5. 스코프 제한 (Non-goals)

- **개체수 수치 시뮬레이션·그래프 없음**(정성 연쇄만). Lotka-Volterra·출생/사망률 파라미터 없음.
- 에너지 효율 10% 법칙 등 정량 규칙 없음(중등 영역).
- 여러 생태계(바다·사막) 동시 없음 — v1은 들/숲 한 세트. 확장 여지만 `v` 필드로 확보.
- 자유 생물 추가/커스텀 종 없음(정의된 12종).

## 6. 제작·배포 절차

1. 스캐폴드:
   ```bash
   node scripts/scaffold-app.js --id eco-web --name "생태계 탐험대" --base immersive \
     --category edu --subcategory edu-sim --emoji 🌿 --desc "먹이그물 잇기·피라미드·평형 시나리오 종합 실험"
   ```
2. `apps.json` 수동 보강: `badge: "시뮬레이션"`, SEO:
   - `seo.title`: `생태계 탐험대 — 먹이그물·피라미드·평형 시뮬레이션`
   - `seo.description`: `먹이그물을 직접 잇고 생태피라미드를 쌓아 보세요. 한 생물이 사라지면 벌어지는 연쇄 변화까지, 초등 5~6학년 생물과 환경을 종합 체험하는 무료 학습 시뮬레이션.`
   - `seo.keywords`: `먹이그물`, `먹이사슬`, `생태피라미드`, `생태계 평형`, `생물과 환경`, `초등 과학`
3. 구현 → `npm run dev` → `npm run inject` → `npm run og` → `npm run sitemap` → 커밋.

## 7. 검수 체크리스트

- [ ] 화살표 방향이 교과 규약(먹힘→먹음)과 일치하고, 역방향 연결이 차단되는가
- [ ] 하나의 정답 그물에 이르는 여러 올바른 사슬이 모두 인정되는가
- [ ] 피라미드 역전 시 시각적 경고가 뜨는가
- [ ] 평형 시나리오 각 단계가 한 문장 인과로 설명되고, 마지막에 평형 회복으로 끝나는가
- [ ] 어디에도 개체수 수치 그래프·미분방정식식 표현이 없는가 (설계 대원칙)
- [ ] 역할 색이 색약 시뮬레이션에서 아이콘과 함께 구분되는가
- [ ] 드래그-연결이 태블릿 터치에서 오작동 없이 동작하는가 (D의 드래그 컴포넌트 재사용 검증)
- [ ] 다크모드 대비·포커스 링·공유 복원 정상
- [ ] inject/og/sitemap 산출물 정상 (개발 가이드 §7 공통 체크 포함)
