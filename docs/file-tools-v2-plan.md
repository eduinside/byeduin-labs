# 파일 용량 줄이기 개선 계획서 1단계 (2026-10-31)

> 상태: **1단계 구현 완료(2026-10-31, 배포 전)**. 대상은 'PDF·이미지 줄이기' 탭. PPTX 탭은 2단계.
> 계획과 다르게 한 점: 그림이 상한의 1.2배 이하이면 크기는 두고 화질만 조절. 다른 그림의 투명 마스크(SMask·Mask)로 쓰이는 그림은 건너뜀. '쪽을 그림으로' 버튼은 500KB 이상 PDF에서 결과가 20% 미만으로 줄었거나 목표를 못 맞췄거나 원본 그대로일 때, 그리고 열지 못한 PDF에만 보임.

대상: `public/apps/file-tools/app.js`, `styles.css`, `src/pages/apps/file-tools/index.astro`
참고: KnifeLemon/Filee(MIT, .NET 데스크톱 앱)의 PDF 압축 방식·프리셋·'줄어들 때만 바꾸기'. 코드는 가져오지 않고 방식만 웹으로 옮긴다.
원칙: 서버 저장 없음(브라우저 안에서 처리), 새 외부 라이브러리 없음(pdf.js·pdf-lib·UTIF·JSZip 그대로).

## 1. 바꾸는 것

### F1. PDF: 그림만 다시 압축 (기본)
pdf-lib로 PDF를 열어 그림 객체(`/Subtype /Image`)만 골라 다시 인코딩한다. 글자·벡터·글꼴·쪽 구조는 그대로.

- 대상
  - `DCTDecode`(JPEG) 그림: 바이트를 그대로 `createImageBitmap`으로 열어 줄인 뒤 JPEG로 다시 넣음.
  - `FlateDecode`·필터 없음 그림, 8비트, 회색/RGB(ICCBased 1·3 포함): `decodePDFRawStream`으로 풀고 PNG 예측(Predictor ≥ 10)을 되돌린 뒤 픽셀로 만든다. 색이 256개 이하면 도표·로고로 보고 손대지 않음, 넘으면 사진으로 보고 JPEG.
- 건너뜀: CMYK, Indexed, 1비트·16비트, JBIG2·CCITT·JPX, ImageMask, 색 키 Mask 배열, Decode 배열, 그 밖에 모르는 형식.
- 크기 기준: 문서에서 가장 큰 쪽의 긴 변(pt)을 목표 DPI로 환산한 픽셀 수(`capPx`). 그림 긴 변이 `capPx × 1.2`를 넘을 때만 `capPx`로 줄인다. (그림이 실제 그려진 크기 계산은 2단계에서 검토. 스캔 PDF는 그림 = 쪽이라 이것으로 충분)
- 바꿔 넣는 조건: 새 그림이 원본 그림보다 10% 이상 작을 때만. 회색 JPEG는 캔버스가 RGB로만 내보내므로 `DeviceRGB`로 바꿈.
- 쪽 썸네일(`/Thumb`) 삭제, 저장은 객체 스트림 사용(pdf-lib 기본).
- 암호 PDF·열 수 없는 PDF는 오류 문구로 알리고 F2를 권한다.

### F2. PDF: 쪽을 그림으로 바꿔 더 줄이기 (선택)
지금 방식(pdf.js로 그리기)을 남기되, 결과 줄의 '쪽을 그림으로 바꿔 더 줄이기' 버튼으로만 쓴다. 쪽 크기는 원래 pt 크기 유지(P2 해결).

### F3. 줄이는 정도 프리셋
| 이름 | DPI | JPEG 화질 | 쓰임 |
|---|---|---|---|
| 가볍게 | 100 | 50% | 메신저·화면으로 보기 |
| 보통(기본) | 150 | 65% | 공문 첨부·대부분 |
| 화질 우선 | 220 | 80% | 인쇄 |
| 용량 정하기 | 탐색 | 탐색 | 'N MB 이하'가 정해진 경우 |

- 낱장 그림(JPG·PNG·TIFF)은 A4 긴 변(11.69인치) × DPI를 긴 변 상한으로 쓴다.
- '용량 정하기'는 숫자 입력 + 빠른 선택(1·2·5·10MB). 기준은 **결과 파일 하나**(합치면 합친 파일). DPI 72~300 × 화질 40~85% 후보를 지금의 이진 탐색(`searchBestUnderTarget`)으로 고른다. PDF가 그림만 줄여서 못 맞추면 결과 줄에 F2 버튼.

### F4. 결과 형식
- 원래대로(기본): PDF→PDF, JPG→JPG, PNG→PNG, TIFF→PDF(브라우저가 TIFF를 못 만듦, 안내).
- PDF: 그림 파일은 쪽 하나짜리 PDF로. 파일이 2개 이상이면 '하나로 합치기' 선택 가능(기본 끔).
- JPG: PDF·TIFF는 쪽마다 한 장, 여러 장이면 ZIP.
- PNG 출력은 뺀다(스캔에서 PNG로 바꾸면 커지기만 함).

### F5. 넣자마자 시작, 파일별 결과
- 파일을 넣거나 설정을 바꾸면 바로 줄이기 시작(한 번에 한 파일씩 차례로). 설정이 바뀌면 진행 중인 결과는 버리고 다시.
- 파일마다 한 줄: 이름 · 상태(기다리는 중/줄이는 중 N%/완료/실패) · '원본 → 결과 (N% 줄어듦)' · [저장] [빼기].
- 아래에 [모두 저장] (1개면 그 파일, 여러 개면 ZIP) · [모두 빼기].
- 설정(정도·형식·목표 MB·합치기)은 localStorage에 기억(실패해도 동작).

### F6. 줄어들 때만 바꾸기
같은 형식인데 결과가 원본보다 작지 않으면 원본을 그대로 두고 '이미 충분히 작아요. 원본 그대로예요'로 표시. 저장하면 원본이 내려받아진다. 형식을 바꾼 경우(TIFF→PDF, 합치기, JPG 변환)는 커져도 결과를 주고 주황색으로 알린다.

## 2. 건드리지 않는 것
- PPTX 탭(2단계: 그려진 크기 기준 축소, 사진/도표 구분, HWPX·DOCX).
- Web Worker·WASM 인코더(3·4단계).

## 3. 확인 방법
브라우저에서 만든 시험 파일로 확인한다.
1. 글자 + 큰 사진 JPEG 1장이 든 PDF → 글자가 남아 있는지(pdf.js `getTextContent`), 용량이 줄었는지.
2. 글자만 있는 PDF → '이미 충분히 작아요'.
3. 큰 JPG·PNG → 같은 형식으로 줄어듦.
4. 여러 파일 + 합치기 → PDF 하나, 쪽 수 합계 일치.
5. 용량 정하기 → 목표 이하 / 못 맞추면 주황 안내와 F2 버튼.
6. 설정 바꾸면 다시 처리, 모두 저장 ZIP.

# 2단계: 문서 파일(PPTX·DOCX·XLSX·HWPX) (2026-10-31)

> 상태: **구현 완료(2026-10-31, 커밋 전)**. 계획과 다르게 한 점: XLSX는 `a:xfrm/a:ext`가 0이면 앵커의 `xdr:ext`를 씀(ExcelJS·Excel 모두 이 방식). 다시 묶을 때 폴더 항목을 새로 만들지 않음(`createFolders: false`).

## 0. 지금 문제 (PPTX 탭)

| # | 문제 |
|---|---|
| Q1 | 모든 그림을 같은 폭(px)으로 자름. 작게 줄여 넣은 큰 사진도, 화면 가득 넣은 사진도 같은 기준 |
| Q2 | 투명 부분이 없는 PNG를 모두 JPEG로 바꿈. 캡처·도표 글자가 뭉개짐. 내용은 JPEG인데 이름은 `.png` 그대로 |
| Q3 | PPTX 한 개, 목표 용량 슬라이더 하나. 1단계 탭과 사용법이 다름 |
| Q4 | DOCX·XLSX·HWPX는 못 줄임(같은 zip 구조인데도) |

## 1. 바꾸는 것

### D1. 탭 하나로
PDF·그림·문서를 한 곳에 넣는다. 줄이는 정도(가볍게/보통/화질 우선/용량 정하기)와 파일별 결과·저장·모두 저장은 1단계와 같다. 결과 형식(원래대로/PDF/JPG)과 합치기는 PDF·그림에만 쓰이고, 문서 파일은 늘 같은 형식으로 나온다. HWP(옛 형식)는 'HWPX로 저장한 뒤 넣어 주세요'로 안내.

### D2. 그려진 크기 기준으로 줄이기
문서 XML에서 그림이 실제로 그려진 크기(인치)를 찾아, 그 크기 × DPI보다 1.2배 넘게 큰 그림만 줄인다. 잘라 쓴 그림(crop)은 잘린 비율만큼 더 크게 잡는다. 쓰임을 못 찾은 그림은 쪽(슬라이드) 긴 변 × DPI를 상한으로.

| 형식 | 그림 폴더 | 쓰임을 찾는 곳 | 크기 |
|---|---|---|---|
| PPTX | `ppt/media/` | 슬라이드·레이아웃·마스터의 `a:blip` → `p:spPr/a:xfrm/a:ext`, 배경은 슬라이드 크기 | EMU(914400/인치), `a:srcRect` |
| DOCX | `word/media/` | 본문·머리글·바닥글 `a:blip` → `wp:inline`/`wp:anchor`의 `wp:extent` | EMU |
| XLSX | `xl/media/` | `xl/drawings/*.xml` `a:blip` → `xdr:pic/xdr:spPr/a:xfrm/a:ext` | EMU |
| HWPX | `BinData/` | `Contents/section*.xml`의 `hp:pic` → `hc:img@binaryItemIDRef`, `hp:curSz`(없으면 `hp:sz`), `hp:imgClip`/`hp:imgDim` | HWPUNIT(7200/인치) |

관계 파일(`*.rels`)·`content.hpf`로 그림 경로를 찾는다.

### D3. 사진/도표 구분
PNG는 가장자리 512px로 줄인 표본(가장 가까운 픽셀)에서 색 가짓수와 투명도를 본다. 256색 이하이거나 투명하면 PNG 그대로(크기만 줄임), 아니면 사진으로 보고 JPEG. JPEG로 바꾼 그림은 확장자를 `.jpg`로 바꾸고 참조를 고친다(OOXML: `*.rels`의 Target, `[Content_Types].xml`의 Default/Override. HWPX: `content.hpf`의 href·media-type, `META-INF/manifest.xml`).

### D4. 그 밖
- 회전 정보(EXIF Orientation ≠ 1)가 든 JPEG는 건너뜀(프로그램마다 회전 처리가 달라서).
- 내용이 같은 그림(SHA-256)은 한 번만 처리하고 쓰임을 합쳐 계산.
- 10% 넘게 줄 때만 바꿈. 다시 묶을 때 원래 무압축(STORE)이던 항목은 그대로 무압축(HWPX `mimetype` 필수).
- 예전 XML 공백 지우기는 뺌(이득이 작고 HWPX 글 공백을 건드릴 위험).

## 2. 확인 방법
- 실제 PPTX(그림 적은 발표 자료) → 깨지지 않고 원본 그대로이거나 조금 줄어듦.
- 실제 HWPX(작게 넣은 큰 PNG) → 크게 줄고, kordoc로 그려 봐서 그림이 보임.
- 사진이 많은 PPTX·DOCX·XLSX를 브라우저에서 만들어 시험: 줄어듦, 관계 파일 대상이 모두 있음, 확장자별 콘텐츠 형식이 있음.

# 3단계: 생활 예시·개인정보·HEIC·회색·HWP 안내·쪽 정리 (2026-10-31)

> 상태: **구현 완료(2026-10-31, 커밋 전)**. 계획과 다르게 한 점: E5 회색은 회색조만으로는 2% 남짓밖에 줄지 않아(브라우저 JPEG가 색 정보를 이미 적게 씀) 종이 색을 흰색으로·글자를 진하게 펴는 단계를 더함(시험 스캔에서 추가로 19% 줄어듦). E6은 남길 쪽만 새 문서로 옮겨 뺀 쪽의 그림까지 빠지게 함(이때 책갈피는 빠짐). 쪽 정리 창 안 알림은 토스트 대신 창 안 상태 줄. HEIC는 실제 파일이 없어 변환 도구 불러오기·실패 안내까지만 확인.
>
> 운영자 결정(갈라진 세션에서 정함): "업무관리 기준(5MB) 등 생활에서 쓸 수 있는 예시 몇 개 넣기 / 1,4,6,8번 추가", 7번(쪽 정리) 방식 "좋아".

| # | 기능 | 방식 |
|---|---|---|
| E1 | HWP 안내 | `.hwp`를 받아 결과 줄에 '한글에서 파일 → 다른 이름으로 저장하기 → 파일 형식 HWPX' 단계를 남김(처리·저장 대상 아님) |
| E2 | 생활 예시 용량 | '용량 정하기' 빠른 선택을 쓰임+수치로: 1MB · 업무관리(5MB, 운영자 제공) · 네이버 메일(10MB) · Gmail(25MB). 기본 목표 5MB. 네이버 수치는 운영자 확인 필요 |
| E3 | 개인정보 지우기(기본 켬) | 다시 그린 그림은 EXIF가 저절로 빠짐(화면에 안내). 켜면 그대로 둔 JPEG의 APP1(EXIF·XMP)·APP13(IPTC), PNG의 eXIf·tEXt·zTXt·iTXt·tIME를 바이트 단위로 지움. 문서 속성: OOXML `docProps/core.xml`의 작성자·마지막 저장한 사람, `app.xml`의 회사·관리자, HWPX `content.hpf`의 creator·lastsaveby, PDF Info의 Author·Creator·Producer와 XMP(`/Metadata`) |
| E4 | HEIC(아이폰 사진) | 넣었을 때만 heic2any(0.0.4) 지연 로드(브라우저가 직접 열 수 있으면 그대로). 결과는 JPG(원래대로), PDF·합치기도 가능 |
| E5 | 회색으로(글자 스캔) | 정도와 별개 체크. PDF·그림의 다시 그린 그림을 회색조로(문서 파일에는 안 씀). 캔버스는 3채널 JPEG만 만들어서 색 정보가 사라지는 만큼 줄어듦 |
| E6 | 쪽 정리 | PDF 결과 줄의 [쪽 정리] → 모달에 쪽 썸네일 격자(pdf.js, 보이는 것부터), 누르면 빼기, ↻ 90도 회전, 거의 흰 쪽은 처음 열 때 빼기로 표시(되돌릴 수 있음) → [적용]하면 다시 압축하는 대신 줄인 결과에 바로 적용, 결과 줄에 'N쪽 중 M쪽 뺌·K쪽 회전'. 합친 줄은 전체 쪽. 설정을 바꿔 다시 처리해도 쪽 정리는 유지(합치는 파일이 바뀌면 초기화) |
