# 채점표 앱 요구사항 정의서

문서 버전: v1.0
대상 레포: `eduinside/byeduin-labs` (신규 앱)
배포 형태: 단일 HTML 파일 (eduin.info 하위 호스팅)
작성일: 2026-05-30

---

## 1. 개요

대회·발표·공모 등에서 사용하는 채점표 도구. 한 명이 표를 만들어 여러 공동 채점자에게 배포하고, 각자 매긴 점수를 다시 모아 종합 결과를 산출한다. 별도 서버·데이터베이스 없이 CSV 파일 주고받기와 브라우저 로컬 저장만으로 전체 흐름이 완결된다.

핵심 사용 흐름은 다음 세 단계다.

1. 주최/수합 담당자가 표 양식을 만들어 채점 양식 CSV로 배포한다.
2. 각 채점자가 양식을 불러와 점수를 입력하고 본인 결과 CSV를 저장한다.
3. 수합 담당자가 결과 CSV들을 모아 채점자별·종합 결과를 산출하고 인쇄/PDF로 내려받는다.

---

## 2. 기술 제약

- 단일 HTML 파일(인라인 CSS·JS). 외부 빌드 도구 없이 바로 실행·호스팅 가능해야 한다.
- 백엔드·데이터베이스 없음. 모든 처리는 클라이언트에서 수행한다.
- 채점 진행 중 데이터 보존은 `localStorage`를 사용한다.
- 채점자 간 데이터 교환은 CSV 파일로 한다.
- 외부 의존성은 폰트(CDN) 정도로 최소화한다.
- 한국어 UI 기준.

## 3. 화면(모드) 구조

상단 탭으로 세 모드를 전환한다.

| 모드 | 이름 | 주체 | 역할 |
|------|------|------|------|
| 1 | 표 만들기 / 배포 | 주최·수합 담당자 | 표 설계, 점수 시뮬레이션, 양식 배포 |
| 2 | 채점하기 | 개별 채점자 | 양식 불러와 점수 입력, 결과 저장 |

## 4. 모드 1 — 표 만들기 / 배포

### 4.1 기본 설정

- 참가 인원수 (1~300)
- 시상 비율 (%, 0~100) — 상위 비율만큼을 시상 대상으로 표시
- 영역 수 (1~12)
- 영역별 입력: 영역 이름, 만점(1 이상)
- 영역 수를 바꾸면 영역 입력 칸이 즉시 늘거나 줄고, 기존 입력값은 유지한다.

### 4.2 점수 생성 규칙

- 점수는 1점 단위 정수.
- 각 영역 점수는 0 이상 해당 영역 만점 이하.
- 표를 처음 만들 때, 그리고 "점수 랜덤" 버튼을 누를 때마다 점수 분포를 다시 계산한다.

### 4.3 시상자 점수 범위 (선택 기능)

- 체크박스로 켜고 끈다. 꺼져 있으면 전 구간 완전 랜덤.
- 최저 %, 최고 %를 지정한다(만점 합계 대비 비율, 기본 80~100).
- 켜진 상태에서 점수를 생성하면:
  - 시상 대상자(상위 인원)의 **총점**이 지정 범위 안에 들어오도록 영역별로 분배한다.
  - 나머지 참가자는 그 범위보다 낮게 배치되어, 시상 대상자가 항상 상위가 되도록 보장한다.
- 분배 시 각 영역 점수는 0~만점을 벗어나지 않고, 영역 점수 합은 목표 총점과 정확히 일치해야 한다.
- 만점 합계를 기준으로 계산하므로 영역 수·만점이 달라져도 비율대로 동작한다.

### 4.4 결과 표

- 열: 순위, 이름, 영역별 점수, 총점, 시상.
- 정렬: 총점 낮은 순 / 높은 순 토글(기본 낮은 순). 정렬은 보기 순서만 바꾼다.
- 순위와 시상 판정은 정렬 방향과 무관하게 총점이 높은 순서를 기준으로 한다.
  - 시상 대상 = 총점 상위 N명 (N = round(인원수 × 시상비율 ÷ 100)).
  - 시상 대상 행은 메달·강조 표시.
- 이름·점수 칸은 직접 수정할 수 있고, 수정 시 총점·순위·시상이 즉시 갱신된다.

> 비고: 현재 정의는 "고득점 = 우수"를 전제로 한다. 기록 경기·벌점처럼 저득점 시상이 필요하면 시상 기준 방향 옵션을 별도 확장한다.

### 4.5 내보내기

- CSV 저장: 점수가 채워진 현재 표를 CSV로 저장.
- 채점 양식 내보내기: 영역·만점·참가자 명단·시상비율은 담되 점수 칸은 비운 배포용 CSV를 저장. 채점자에게 전달한다.

### 4.6 입력 UI

- 설정 화면의 모든 숫자 입력은 좌우 −/+ 버튼이 달린 스테퍼로 제공한다.
- 버튼 클릭과 직접 입력을 모두 지원하며, 각 항목의 min/max·증감 단위(step)를 지킨다.
  - 예: 비율·만점·범위 %는 5단위, 인원수·영역 수는 1단위.
- 채점 입력 표(모드 2)의 점수 칸은 항목이 많아 스테퍼를 적용하지 않는다.

---

## 5. 모드 2 — 채점하기

- 채점자 이름 입력.
- 배포받은 채점 양식 CSV 불러오기. 불러오면 영역·만점·참가자 명단을 그대로 재현하고 점수 칸은 비워 둔다.
- 점수 입력 표: 영역별 점수 입력, 행별 총점 자동 계산.
- 진행률 표시(입력 완료 인원 / 전체 인원).
- 입력 즉시 `localStorage`에 자동 저장. 브라우저를 닫았다 다시 열거나 모드를 재진입해도 이어서 채점할 수 있게 자동 복구한다.
- 내 채점 결과 저장: 채점자 이름이 담긴 결과 CSV로 저장. 미입력 칸이 있으면 경고 후 진행 여부를 확인한다.
- 초기화: 저장된 채점 내용을 지운다(확인 후 실행).

---

## 6. 모드 3 — 수합하기

- 채점자 결과 CSV 여러 개를 한 번에 불러온다.
- 동일 채점자 파일을 다시 불러오면 덮어쓰기 되어 중복이 생기지 않는다(채점자명 기준).
- 참가자 매칭은 이름 기준으로 한다.

### 6.1 종합 결과 표

- 열: 순위, 이름, [채점자별 총점…], 합계, 평균, 시상.
- 특정 참가자를 채점하지 않은 채점자 칸은 빈 값으로 표시하고, 합계·평균은 점수가 있는 채점자만으로 계산한다.
- 정렬: 종합 낮은 순 / 높은 순 토글.
- 집계 기준: 합계 / 평균 토글. 순위·시상은 선택한 집계 기준의 상위 N명.
- 시상 비율은 불러온 파일에 저장된 값을 따른다.

### 6.2 채점자별 상세 표

- 채점자마다 영역별 점수까지 포함한 표를 순서대로 보여준다.
- 순위는 해당 채점자 총점 기준 등수.

### 6.3 인쇄 / PDF

- 인쇄 버튼으로 브라우저 인쇄를 호출하고, 대상에서 "PDF로 저장"을 선택해 내려받는다.
- 인쇄 시 탭·버튼·배경 등 화면 전용 요소는 제외하고 표만 깔끔하게 출력되도록 인쇄 전용 스타일을 둔다.

## 7. CSV 포맷 명세

UTF-8(BOM 포함). 메타 행은 `#`으로 시작하고, 그 뒤에 헤더 행과 데이터 행이 온다.

```
#FORMAT,scoringtable,v1
#SCORER,<채점자명>
#RATIO,<시상비율 정수>
#AREAS,<영역명>:<만점>|<영역명>:<만점>|...
이름,<영역1명>,<영역2명>,...,총점
<참가자명>,<점수>,<점수>,...,<총점>
...
```

규칙:

- 영역 정보는 `영역명:만점`을 `|`로 이어 붙인다. 만점은 마지막 `:` 뒤의 값으로 읽는다.
- 영역명에 포함된 `|`, `:`는 저장 시 공백으로 치환한다.
- 셀에 쉼표·따옴표·줄바꿈이 있으면 큰따옴표로 감싸고 내부 따옴표는 두 개로 이스케이프한다(표준 CSV).
- 배포용 양식: `#SCORER`는 빈 값, 점수·총점 칸은 비운다.
- 결과 파일: `#SCORER`에 채점자명, 점수·총점 채움. 채점자명을 못 읽으면 파일명을 채점자명으로 대체한다.
- `#RATIO`, `#AREAS` 정보는 양식·결과 모두에 유지되어 수합 단계에서 그대로 활용된다.

## 8. 데이터 모델 (런타임)

```
Area  = { name: string, max: number }
Row   = { name: string, scores: (number|null)[] }   // null = 미입력
Form  = { scorer: string, ratio: number, areas: Area[], rows: Row[] }
```

- 총점 = scores 합(미입력은 0으로 간주하거나 미입력 표시).
- 모드 2 localStorage 저장 형태: `{ name: 채점자명, form: Form }`.

## 9. 디자인 / byeduin-labs 통합 지침

최종 디자인은 byeduin-labs 신규 앱의 공통 패턴(레이아웃·색·타이포·컴포넌트 톤)에 맞춰 교체한다. 아래는 그 교체를 쉽게 하기 위한 원칙이다.

- 색·간격·라운드 등 시각 토큰은 `:root`의 CSS 변수로 모아 두고, 레포 공통 토큰으로 갈아끼울 수 있게 한다.
- 폰트는 레포 컨벤션을 따른다(현재 잠정으로 Pretendard 사용 중).
- 라이트 테마 기준, 표 가독성과 인쇄 결과를 우선한다.
- 구조(탭 → 패널 → 표)와 동작 규칙은 디자인과 분리해 유지한다. 디자인 교체가 기능에 영향을 주지 않아야 한다.
- 강조는 굵게 남발하지 않고 색·배치로 처리한다.

현재 구현된 잠정 스타일(추후 교체 대상): 페이퍼 톤 배경, 세이지 그린 주색, 골드 시상 강조, 카드형 패널, 스티키 표 헤더.

## 10. 비기능 요구

- 인원 300명·영역 12개 규모에서 입력·정렬·렌더가 끊김 없이 동작.
- 오프라인에서 동작(폰트 캐시 이후).
- 잘못된/깨진 CSV를 불러와도 앱이 멈추지 않고 사용자에게 알린다.
- 파일·로컬 저장 외에 외부로 데이터를 전송하지 않는다.

---

## 11. 향후 확장(후보)

- 시상 기준 방향 선택(고득점/저득점).
- 수합 단계에서 시상 비율 재지정.
- 동점자 처리 규칙(공동 순위) 명시.
- 영역별 가중치.
