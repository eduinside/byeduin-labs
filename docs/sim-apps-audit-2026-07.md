## 1. 앱별 조사 결과

### 1-1. moon-phase (달의 위상 v1)

**현황**: Julian Date 기반 평균 이각 계산으로 월령 산출. 달 렌더 + 궤도 뷰 + 초저녁 하늘 시뮬 3개 캔버스. app-shell 공통 크롬 사용.

| 구분 | 발견 사항 | 심각도 |
|---|---|---|
| 버그 | **슬라이더 ↔ 날짜 비동기**: 슬라이더로 위상을 바꿔도 `currentSimDate`가 갱신되지 않아, "N월 N일의 초저녁 하늘" 라벨이 이전 날짜로 남고, 이후 ▶재생을 누르면 슬라이더 위치를 무시하고 옛 날짜부터 재생됨 (`index.html:417-421`, `522-524`) | 높음 |
| 버그 | `new Date(dateInput.value)`는 UTC 자정으로 파싱 → KST에서 9시간 오프셋. 월령 0.3일 수준 오차 + 날짜 경계에서 하루 어긋날 수 있음 (`index.html:411`) | 중간 |
| 잔재 | `shareMoonPhase()`가 정의만 되고 어디서도 호출 안 됨(공유는 app-shell이 주입) — 죽은 코드 (`index.html:811`) | 낮음 |
| UX | 캔버스가 340/550px 고정 → 모바일 1열 전환 시 좌우 잘림 가능. 반응형 재계산 없음 | 중간 |
| 구조 | v2(`moon-phase-v2`)와 공존 중. v1에는 volcano식 미션·퀴즈 흐름 없음 — 계획 문서상 v2가 담당이므로 v1은 정확성·버그만 유지보수하는 게 맞음 | 참고 |

### 1-2. volcano (화산 탐험대) — 벤치마크 앱

**현황**: MapLibre + Esri 위성 + Terrarium DEM 3D 지형. 인트로 → 자유탐험 → 퀴즈 → 결과 정리의 검증된 골격. `mapFallback`으로 WebGL/네트워크 실패 대응까지 완비. 5개 중 가장 완성도 높음.

| 구분 | 발견 사항 | 심각도 |
|---|---|---|
| UX | 결과 화면에서 산 이름 클릭(`revisit`) 시 지도만 이동하고 사이드 패널은 결과 화면 유지 → 해당 산의 관찰 포인트·해설을 다시 볼 수 없음. "결과로 돌아가기" 버튼과 함께 해설 재표시가 자연스러움 (`index.html:568-574`) | 중간 |
| UX | "다시 탐험하기"가 `location.reload()` → 지도 타일 전부 재로딩. `start()` 재호출로 대체 가능 | 낮음 |
| 외부 의존 | Esri/AWS 타일은 학교망 차단 시 지도가 빈 화면이 될 수 있으나 fallback 있음. 타일 오류는 console.warn만 하므로, 연속 실패 시 fallback 전환 조건 추가 여지 | 낮음 |
| 접근성 | 퀴즈 정오답 피드백에 `aria-live` 없음(5개 앱 공통) | 낮음 |

### 1-3. step-squad (계단수 블록)

**현황**: 삼각수 개념 → 빌더(1~20단) → O/X 퀴즈. 로직은 단순·정확(`getStepRank`).

| 구분 | 발견 사항 | 심각도 |
|---|---|---|
| 버그 | JS 인라인 스타일이 `'Fredoka One',cursive` 폰트를 참조하지만 로드하는 폰트는 Dongle뿐 → 수식·라벨이 시스템 cursive로 표시됨 (`step-squad.html:656`, `889`, `898`) | 중간 |
| 레이아웃 | `.explainer`가 `grid-template-columns: repeat(4,1fr)` 고정, 미디어쿼리 없음 → 모바일에서 카드 4개가 짓눌림 (`step-squad.html:482-487`) | 중간 |
| 레이아웃 | `.range-labels`의 `padding-left:114px` 하드코딩 → 좁은 화면에서 눈금 어긋남 (`step-squad.html:651`) | 낮음 |
| 죽은 코드 | `.c1`~`.c20` 블록 색상 클래스 정의 후 미사용(전부 인라인 스타일로 생성), `.staircase`/`.column`/`.block`도 미사용 | 낮음 |
| 일관성 | break-make는 별·도장 localStorage 기록이 있는데 step-squad 퀴즈 점수는 휘발성 — 시리즈 내 보상 체계 불일치 | 중간 |
| 학습 설계 | 퀴즈가 O/X 단답에 그침. 오답 시 "몇 단까지 쌓으면 몇 개 남는지" 시각화하면 volcano식 '관찰→교정' 흐름에 가까워짐 | 제안 |

### 1-4. break-make (가르기 모으기)

**현황**: 3종 중 가장 완성도 높음. localStorage 진행 기록(별/도장/도감), 받침 기반 조사 처리, 도전 모드, 십몇(10묶음+낱개) 단계까지 교육 설계가 탄탄함.

| 구분 | 발견 사항 | 심각도 |
|---|---|---|
| 버그성 | **도전 모드가 '십몇' 단계에서 무동작**: 토글은 켜지지만 `given`이 `!isTeen`에서만 생성되어 아무 변화 없음 → 사용자는 고장으로 인식 (`break-make.html:708`, `853`) | 중간 |
| UX | 십몇 가르기에서 '10묶음+낱개' 정답만 인정(`checkTeenDone`) — 교육 의도는 명확하나, 예컨대 13→6+7 시도가 "10 묶음과 낱개를 나눠 담아요!"로만 반려됨. 왜 그 방식인지 힌트 한 줄 보강 여지 | 낮음 |
| 접근성 | 구슬 탭 인터랙션이 마우스/터치 전용 — 키보드 조작 불가(시리즈 공통) | 낮음 |

### 1-5. club-badge (clubs)

**현황**: 16개 클럽(약수·소수·삼각수·제곱수 등) 데이터 분리(`clubs-data.js`) 구조 양호. 탐색기 + 3지선다 퀴즈.

| 구분 | 발견 사항 | 심각도 |
|---|---|---|
| **버그** | **오답 선택지가 실제로는 정답일 수 있음**: 오답 풀을 `CLUBS.filter(c => c.id !== 정답.id)`로만 뽑아, n이 속한 다른 클럽이 '오답'으로 출제됨. 예: n=12에서 정답이 '3 클럽'일 때 '짝수 탑'·'슈퍼 직사각형'이 오답 선택지로 나오고 고르면 틀림 처리. **`!c.check(n)` 필터 필수** (`clubs.html:1083`) | **높음** |
| 버그성 | 정답 버튼 하이라이트를 `textContent.includes(nameKo)`로 판별 — 클럽명이 다른 클럽명의 부분 문자열이 되는 순간 깨지는 취약한 매칭. data 속성 비교로 교체 필요 (`clubs.html:1111`) | 중간 |
| 엣지 | 퀴즈 n 범위가 0~100: n=0이면 정답 후보가 '짝수 탑'뿐이고 "0 ÷ 2 = 0" 해설 — 저학년에게 0의 짝수성은 논쟁적. 1~100으로 좁히는 게 안전 (`clubs.html:1065`) | 중간 |
| 품질 | `getClubReason`의 squares-holes가 "a²-b² 형태"라고만 출력 — 실제 분해(예: 12=4²-2²)를 계산해 보여줄 수 있음. super-rect/super-duper 해설도 문구 동일 | 낮음 |
| 기술 | rainbow-sevens SVG의 `id="rainbow"` 그라디언트가 카드·모달·퀴즈에 중복 삽입 → 문서 내 중복 ID. 접두사 부여 필요 (`clubs.html:865`) | 낮음 |

## 2. 시리즈 공통(횡단) 이슈

1. **코드 중복**: blocks-universe 3개 앱이 효과음(Web Audio)·토스트·공유·음소거·홈/공유 오버레이 버튼 코드를 각각 복사해 보유(~120줄 × 3). 공통 모듈(`blocks-universe/common.js` 또는 기존 `app.js`)로 추출하면 유지보수 비용 1/3.
2. **셸 이원화**: moon-phase/volcano는 `app-shell.js` 공통 크롬, blocks-universe 3종은 수제 오버레이. 장기적으로 app-shell 편입 검토.
3. **공유 기능**: 5개 모두 단순 URL 복사만 지원. `vives-share` 패턴(#share= 상태 인코딩)을 적용하면 "내가 만든 7단 계단", "13의 클럽 결과" 같은 상태 공유 가능.
4. **접근성**: 퀴즈 피드백 `aria-live` 부재, 키보드 조작 불가, 색상만으로 정오답 구분(일부) — 시리즈 일괄 체크리스트로 처리할 사안.

## 3. 역할 분담 제안 (Fable 직접 vs Sonnet 위임)

### Fable이 직접 처리할 요소 — 판단·설계가 필요한 작업

| 작업 | 이유 |
|---|---|
| club-badge 퀴즈 오답 풀 버그 수정 | 단순 필터 추가처럼 보이지만, n이 여러 클럽에 속할 때 오답 3개를 못 채우는 경우(예: n=24는 8개 클럽 소속)의 폴백 설계가 필요 — 출제 로직 재설계 판단 동반 |
| moon-phase 슬라이더·날짜 동기화 + UTC 파싱 수정 | 슬라이더 이동 시 날짜를 역산할지, 날짜 표시를 숨길지의 UX 결정 + 천문 계산 검증이 얽힘 |
| break-make 십몇 도전 모드 처리 방향 결정 | "십몇에서 토글 비활성화" vs "십몇용 도전 문제 신설" — 교육 설계 결정 |
| blocks-universe 공통 모듈 추출 설계 | 3개 앱의 미묘한 차이(음소거 저장 키·위치)를 통합하는 인터페이스 결정 |
| step-squad 퀴즈 오답 교정 시각화 설계 | "몇 개 남는지" 보여주는 학습 흐름 설계는 volcano 공식 이식 판단 필요 |
| 교육 콘텐츠 정확성 검수 | 0의 짝수성 취급, 달 관측 방향 문구, 십몇 가르기 힌트 문구 등 오개념 리스크 검토 |

### Sonnet에 위임 가능한 처리 포인트 — 명세가 명확한 기계적 작업

각 항목은 "무엇을 어떻게"가 이 보고서로 이미 확정되어, 스펙만 주면 검증 가능한 작업:

1. **step-squad 폰트 정리**: Fredoka One `<link>` 추가 또는 참조를 Dongle로 치환(둘 중 하나로 지시).
2. **반응형 CSS 패치**: `.explainer` 미디어쿼리(2열/1열), `.range-labels` padding 하드코딩 제거.
3. **죽은 코드 제거**: step-squad `.c1~.c20`·`.staircase` 계열, moon-phase `shareMoonPhase` 잔재.
4. **club-badge SVG ID 중복 해소**: 그라디언트 ID에 컨텍스트 접두사 부여.
5. **club-badge 정답 버튼 매칭 교체**: `textContent.includes` → `data-club-id` 비교.
6. **`getClubReason` 개선**: squares-holes 실제 a²-b² 분해 계산, super-rect/duper 문구 차별화(공식 명세 첨부 시).
7. **접근성 일괄 패치**: 5개 앱 퀴즈 피드백에 `aria-live="polite"`, 버튼 aria-label 점검 — 체크리스트 기반 반복 작업.
8. **volcano 소소한 개선**: `location.reload()` → `start()` 교체, revisit 시 해설 패널 재표시(동작 명세 확정 후).
9. **vives-share 적용**: 스킬 문서에 패턴이 완비되어 있으므로 앱별 상태 스키마만 정해주면 위임 가능.

### 권장 진행 순서

1. **Fable**: club-badge 퀴즈 버그(사용자가 정답을 골랐는데 틀림 처리되는 유일한 '학습 신뢰' 훼손 버그) → moon-phase 동기화 → break-make 도전 모드 방향 결정
2. **Sonnet 배치 위임**: 위 1~7번을 한 세션 스펙으로 묶어 처리 (파일 5개, 상호 독립)
3. **Fable**: 공통 모듈 추출 + step-squad 학습 흐름 개선 (구조 변경이므로 마지막)
