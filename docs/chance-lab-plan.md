| 항목 | 값 |
|------|-----|
| 앱 ID | `chance-lab` (`/apps/chance-lab/`) |
| 이름 · 이모지 | 가능성 실험실 · 🎲 |
| 셸 | `column` / `medium`(720) — 실험 장치 + 누적 그래프의 대시보드형 세로 흐름 |
| 카테고리 | `edu` / `edu-sim` · 배지 `시뮬레이션` |

| 교과 | 수학 5학년 2학기 「평균과 가능성」(가능성을 말과 수로 표현) · 6학년 「비율」 연계 |
| 대상 기기 | 태블릿·PC·스마트폰 |

### 학습 목표 (성취기준 수준)
1. 일이 일어날 가능성을 말로 표현한다: **불가능하다 ~ 반반이다 ~ 확실하다**.
2. 가능성을 수(0, 1/2, 1 및 분수)로 표현한다.
3. 실험 횟수가 많아질수록 실제 비율이 가능성(이론값)에 가까워짐을 관찰한다.
4. 원하는 가능성을 갖는 장치(회전판)를 **직접 설계**한다 — 역방향 사고.

### 오개념 교정 포인트
- **"앞면이 3번 연속 나왔으니 다음은 뒷면"(도박사의 오류)** → 매 회 독립임을 연속 실험으로 체감(미션 ②의 핵심).
- **"10번 던지면 정확히 5번 나온다"** → 적은 횟수에선 크게 벗어남 + 많은 횟수에선 비율이 접근함을 동시에 보여줌.

## 2. 화면 흐름 (volcano 골격의 column 적용)

```
[인트로 카드] → [자유 탐험: 실험실] → [미션 4개] → [결과 정리]
```

### 2-1. 인트로
- 미션 카드: "동전을 1000번 던지면 앞면이 몇 번 나올까요? 직접 확인해 봐요!" + `시작하기`.

### 2-2. 자유 탐험 — 실험실

**장치 3종** (탭 전환):
| 장치 | 결과 | 이론 가능성 | 역할 |
|------|------|------|------|
| 🪙 동전 | 앞/뒤 | 1/2 | "반반"의 기준 경험 |
| 🎲 주사위 | 1~6 | 각 1/6 | 결과가 여럿일 때의 가능성 |
| 🎡 회전판 | 색 영역(2~6칸) | **사용자가 설계** | 가능성 0~1 조절 체험 — 이 앱의 차별점 |

**실험 컨트롤**: `1번` `10번` `100번` `1000번` 버튼 + `처음부터`(누적 초기화).

**결과 패널** (장치 아래 상시 표시):
- **누적 막대그래프**: 결과별 횟수 막대 + **이론값 점선**(예: 동전이면 전체의 1/2 위치). 막대에 횟수·비율(%) 병기.
- **수렴 라인 차트**: X축 누적 시행 수(로그 눈금 아님 — 초등 수준, 구간 샘플링으로 단순화), Y축 대상 결과의 비율. 이론값 수평 점선과의 간격이 좁아지는 모습이 핵심 장면.
- 상단 요약 문장 자동 갱신: "지금까지 340번 중 앞면 168번 — **거의 반반**이에요!"

**애니메이션 정책** (성능 설계의 핵심):
| 시행 | 연출 |
|------|------|
| 1번 | 실물 애니메이션 — 동전 플립 0.6s / 주사위 굴림 0.6s / 회전판 스핀 1.0s(감속 이징) |
| 10번 | 축약 연출 0.1s×10 연속, 그래프 실시간 성장 |
| 100 · 1000번 | 개별 연출 생략 — 결과를 배치 계산 후 그래프만 requestAnimationFrame으로 프레임당 집계분씩 차오르게(총 1.5s 내) |

- 실행 중 컨트롤 잠금(중복 실행 방지), `건너뛰기` 탭으로 즉시 완료.

**회전판 설계 모드**: 색 영역 2~6칸, 각 칸을 스테퍼로 1~11칸 비중 조절(전체 12칸 고정 분할 — 각도 자유 조절 대신 12등분 스냅으로 단순화·판정 명확화). 설계한 회전판으로 즉시 실험 가능.

### 2-3. 미션 (4개)
| # | 유형 | 내용 |
|---|------|------|
| ① 말로 표현 | 상황 카드를 교과 **5단계 표현**(`불가능하다`·`~아닐 것 같다`·`반반이다`·`~일 것 같다`·`확실하다`) 축에 드래그(또는 탭) 분류 — "주사위 눈이 7"(불가능하다), "주사위 눈이 3 미만"(~아닐 것 같다), "동전 앞면"(반반이다), "주사위 눈이 3 이상"(~일 것 같다), "주사위 눈이 1~6"(확실하다) 등. **드래그 불가 대비: 카드 탭 → 단계 탭의 2탭 분류 병행** |
| ② 예측→실험 | "동전 10번 — 앞면 몇 번?" 예측 입력 → 실험 → "딱 맞았나요? **적게 던지면 벗어나기 쉬워요.**" → 이어서 1000번 → 비율이 1/2에 가까워짐 관찰 |
| ③ 수렴 관찰 | 주사위 1000번 후 "눈 3이 나온 비율은 어디에 가까워졌나요?" — 1/2 · 1/3 · **1/6** 3지선다 |
| ④ 설계 미션 | "**노랑이 나올 가능성이 3/4인 회전판**을 만들어 보세요" (12칸 중 9칸) → 설계 후 100번 실험으로 자기 검증 |

- ②는 예측 입력 없이는 실험 버튼이 잠김(예측→확인 원칙).
- 별점: ①③ 정답 기준, ②는 참여 완료 기준(예측이 틀리는 게 정상이므로 정오 판정 없음 — "벗어남" 자체가 학습 내용), ④는 설계 정확도 기준.

### 2-4. 결과
- 별점 + 배움 정리 카드: "가능성은 0(불가능)부터 1(확실) 사이의 수로 나타낼 수 있어요. **실험을 많이 할수록 결과는 가능성에 가까워져요.**"
- `다시 도전` / `실험실로` / 공유(내가 설계한 회전판).

## 3. 기술 설계

### 3-1. 난수·집계
- `Math.random()` 사용, 시드·가중치 조작 없음(**편향 연출 금지** — 교육 도구로서 정직성이 우선. "수렴 안 하는 날"도 그 자체로 정직한 데이터).
- 1000번 배치는 루프 한 번에 계산해 카운트 배열만 갱신 — 개별 시행 기록을 배열로 쌓지 않음(메모리·성능). 수렴 차트용으로는 **구간 스냅샷**(누적 10, 20, 50, 100, 200, …마다 비율 1개)만 보관, 최대 60포인트 상한.

### 3-2. 렌더링
- 그래프는 **SVG 직접 렌더**(차트 라이브러리 금지 — 외부 CDN 0 원칙). 막대 + 폴리라인 + 점선 3요소뿐이라 라이브러리 불필요.
- 장치 애니메이션: CSS transform 키프레임(동전 rotateX 플립, 회전판 rotate + cubic-bezier 감속). 회전판 정지 각도는 결과가 먼저 결정된 뒤 역산(결과 조작이 아니라 연출 동기화).

### 3-3. 상태 모델
```
state = {
  device: 'coin' | 'dice' | 'spinner',
  counts: { coin: [앞, 뒤], dice: [6], spinner: [칸별] },
  total:  { coin, dice, spinner },
  snapshots: [ { n, ratio } ],            // 수렴 차트용, 장치별
  spinner: { slots: [ { color, weight } ] }   // weight 합 = 12
}
```

### 3-4. 저장 · 공유
- `localStorage` 키: `chance-lab:v1` → `{ missions, spinner, counts?, total? }` — 실험 누적은 저장하되 용량 무시 가능 수준(카운트뿐).
- 공유: `#share=` payload `{ v: 1, spinner }` — **회전판 설계만** 공유(실험 결과 공유는 의미 없음). 수신 측은 그 회전판이 장착된 실험실로 진입. `shareCurrentPage()` 단축링크.

### 3-5. 의존성
- 외부 CDN 0. 오프라인 완전 동작. Web Audio 미사용(효과음 없음 — 리듬 메이커에서 확립 후 후속 검토).

## 4. 디자인

- 공통 3종 + 표준 스크립트, `column`/`medium`, `.app-header` 표준.
- 팔레트: 실험실 톤 — `--cl-bar`(실험 막대), `--cl-theory`(이론값 점선, 주의를 끄는 대비색), `--cl-hit`(요약 문장 강조). 회전판 색상은 색약 안전 팔레트 6색 고정(색명 라벨 병기: 노랑·파랑…).
- 그래프 텍스트(축·비율)는 12px 이상, 다크모드에서 점선·막대 대비 확인.
- 버튼 4개(1/10/100/1000)는 동일 행 배치, 터치 타깃 ≥ 44px.

## 5. 스코프 제한 (Non-goals)

- 두 사건 조합(동전 2개, 주사위 합) 없음 — 중등 영역.
- "확률" 용어, 기대값, 표본공간 등 교육과정 밖 용어 없음.
- 실험 이력의 개별 시행 로그·리플레이 없음(카운트만).
- 효과음 없음(v1).

## 6. 제작·배포 절차

1. 스캐폴드:
   ```bash
   node scripts/scaffold-app.js --id chance-lab --name "가능성 실험실" --base column --width medium \
     --category edu --subcategory edu-sim --emoji 🎲 --desc "동전·주사위·회전판 1000번 실험으로 가능성 체험"
   ```
2. `apps.json` 수동 보강: `badge: "시뮬레이션"`, SEO 확정:
   - `seo.title`: `가능성 실험실 — 동전·주사위·회전판 시뮬레이션`
   - `seo.description`: `동전과 주사위를 1000번 던지고 나만의 회전판을 설계해 보세요. 초등 수학 5학년 가능성 개념을 실험으로 익히는 무료 학습 시뮬레이션.`
   - `seo.keywords`: `가능성`, `수학 5학년`, `동전 던지기`, `주사위 시뮬레이션`, `회전판`, `초등 수학`
3. 구현 → `npm run dev` → `npm run inject` → `npm run og` → `npm run sitemap` → 커밋.

## 7. 검수 체크리스트

- [ ] 1000번 배치가 저사양 기기에서 1.5s 내 완료되고 UI가 멈추지 않는가
- [ ] 수렴 차트가 스냅샷 60포인트 상한을 지키며 왜곡 없이 그려지는가
- [ ] 회전판 정지 각도와 집계 결과가 항상 일치하는가 (연출-결과 동기화)
- [ ] 미션 ②에서 예측 입력 전 실험 버튼이 잠기는가
- [ ] 미션 ④ 판정: 12칸 중 정확히 9칸 노랑일 때만 통과하는가 (동치 배치 모두 인정)
- [ ] "확률"·"대수의 법칙" 문구가 UI 어디에도 없는가 (용어 원칙)
- [ ] 회전판 색상이 색약 시뮬레이션에서 구분되고 색명 라벨이 병기되는가
- [ ] 실행 중 컨트롤 잠금·건너뛰기 동작, 다크모드 그래프 대비, 포커스 링 정상
- [ ] 공유 링크로 회전판 설계가 복원되는가 (진도 미침범)
- [ ] inject/og/sitemap 산출물 정상 (개발 가이드 §7 공통 체크 포함)
