## 1. 한눈에 보기

**겹침은 생각보다 적습니다.** 1280×720과 844×390에서는 40개 페이지 모두 겹침·가로 넘침이 측정되지 않았습니다. 375px에서 걸린 곳은 아래뿐입니다.

| 화면 | 실측 결과 |
|---|---|
| notion-styler (375px) | **페이지가 가로로 30px 넘침.** 색 칸 11개 고정 그리드 때문. 설명 문장·정렬 버튼·오른쪽 위 공유 버튼이 화면 밖으로 잘림 |
| blocks-universe (375px) | 오른쪽 아래 "▶ 재생목록 185" 플로팅 버튼(156×48)이 아래 요약 카드 글자를 가림. 아무것도 고르지 않았는데 185가 표시돼 무엇의 개수인지 모호 |
| timer (코드) | 아래 고정 컨트롤 바(추가·테스트·백업·복구·기록) 위로 공용 토스트가 2.5~8초 겹침. 요일 탭은 '금'까지만 보이고 토·일은 넘겨야 보이는데 신호가 없음 |
| 홈·read-tree·octonauts (375px) | 가로 칩 줄이 화면 밖으로 이어지는데 스크롤바가 숨겨져 넘긴다는 신호가 없음 |

## 2. 여러 앱에 걸친 개선 (공통 규칙으로 정하면 한 번에 정리됨)

### 2.1 버튼 체계 통일 — "버튼의 느낌이 이질적이지 않은가"
- 앱마다 버튼 클래스가 따로입니다: `.ck-btn` 48px, `.pk-btn` 44px, `.sc-btn` 36px, `st-btn`, `ms-tb-btn`, `gm-btn`, `fd-btn`(grid-maker가 재정의), `fb-btn`(fraction-bar와 chance-lab이 같은 이름을 다른 모양으로). `design-system.md`의 `.fd-btn`은 사실상 쓰이지 않습니다.
- **위험(삭제) 버튼 표현이 제각각**: 정의 없는 `.danger`(fraction-bar), 이동 버튼에 빨강(chance-lab "← 자유 탐험"), 다운로드에 빨강(tts-reader MP3), 파란 배경+빨간 글자(picker 삭제 확인: `primary`와 `danger`가 동시에 붙음), 인라인 빨강(idea-lab), 중립 회색(timer "기록 삭제", book-share "전체 초기화").
- **핵심 동작이 아이콘뿐**: notion-styler 복사, yt-thumb 분석 시작.
- 제안: 공용 `app-shell.css`에 `primary / secondary(ghost) / danger / icon` 4종과 크기 2종(기본 44px, 작게 36px)을 두고, 새로 고치는 앱부터 옮깁니다. 규칙: ① 화면당 primary 1개 ② 삭제는 danger + 줄 끝 + 확인 또는 되돌리기 ③ 이동·다운로드에 danger 금지.

### 2.2 공통 상단 버튼
- `public/common/app-shell.js:33` 홈 버튼 `<span>Home</span>` → "홈".
- 테마 버튼(💻☀️🌙)·동기화 버튼(🔄)은 이모지, 공유·홈은 lucide 선 아이콘 → 같은 줄의 양식이 다릅니다(스크린샷에서 확인). 셋 다 lucide(`monitor`/`sun`/`moon`/`refresh-cw`)로 맞추는 것을 권합니다.
- 테마 버튼 이름이 "보기 모드"(홈)·"테마 변경"(앱)·"라이트 모드"(title)로 셋. "화면 모드: 자동/밝게/어둡게" 하나로.
- immersive 셸(시뮬레이션·시계)은 테마 버튼이 숨겨져, 다크 토큰을 갖춘 앱도 전자칠판에서 모드를 바꿀 수 없습니다.

### 2.3 화면 아래 겹침
- 공용 토스트(bottom 24px)가 아래 고정 바와 겹침: timer 컨트롤 바, clock 큰 시계 바, seating 상태줄. `VUI.toast`에 `--vui-toast-bottom` 변수(또는 옵션)를 두고 앱이 바 높이만큼 올리면 됩니다.
- 아래 고정 요소에 `env(safe-area-inset-bottom)` 미반영(timer).

### 2.4 모바일 높이·입력
- `100vh` → `100dvh`: search 레이아웃, md-editor 편집 영역, vui-dialog(`ui.js:46`), 홈 모달, picker·seating·clock 모달.
- 몰입형 화면의 잘림: fraction-bar·chance-lab은 `body{overflow:hidden}` + `min-height:100vh`라 **휴대폰 가로(844×390)에서 인트로의 '시작' 버튼에 닿지 못할 수 있음**(추정). graph-maker의 `height:100dvh; overflow-y:auto` 패턴을 `sim-kit.css`로 올리기를 권합니다.
- iOS는 16px 미만 입력칸에서 화면을 확대합니다: search(14~15px), picker(15px), seating(13~14px). 모바일에서 입력칸 16px.
- 화상 키보드와 부딪힘: idea-lab 무대 `sticky 34vh`, md-editor `calc(100vh - …)`, tts-reader `focus()`.

### 2.5 넘침 신호
가로 스크롤 줄에서 스크롤바를 숨긴 곳(홈 카테고리 칩, read-tree 레벨, octonauts 필터, timer 요일)은 오른쪽 끝 페이드를 넣고, 활성 칩은 `scrollIntoView({inline:'nearest'})`.

### 2.7 같은 것을 다르게 부르는 말
- 백업/복구 ↔ JSON 내보내기/불러오기 ↔ 파일로 저장
- 되돌리기(버튼) ↔ 취소했습니다(토스트) — chalkboard
- 명단 ↔ 명부, 떨어뜨릴 쌍 ↔ 분리 위반 ↔ 떨어뜨릴 짝 — seating
- 대화 목록 ↔ 대화 이력 ↔ 검색 기록 — search (실제는 질문 단위 저장이라 "최근 질문"이 정확)
- 코드로 저장 ↔ 동기화 ↔ 서버 — math-sheet
- 히스토리 ↔ 최근 검색 — yt-thumb
- md-editor를 qr은 같은 창, yt-thumb은 새 창으로 엶

### 2.10 속도

### 2.11 셸 규칙 충돌
- 앱이 `.app-main` 클래스를 자체 레이아웃에 쓰면 셸 패딩이 걸림(search, 실측). 셸 선택자를 `body > .app-main`으로 좁히거나 문서에 금지 규칙 기재.
- file-tools·qr은 `body`에 flex·패딩을 직접 주고 폭 440px 고정, padlet은 정의되지 않은 `bodyWidth="normal"`(→ 720px, 2열이 비좁음). 전자칠판에서 앱마다 폭이 들쭉날쭉.
- search는 다크 판단을 `prefers-color-scheme`으로 해서 테마 버튼 선택(`data-theme`)과 어긋남(OS 다크 + 앱 라이트 선택 시 탭 구분 사라짐).
- 예전 보라색 `rgba(124,106,247)`이 file-tools·notion 2종·qr·yt-thumb의 강조 배경에 남아 파란 primary와 섞임.

### 2.12 구형 기기

## 4. 앞으로 쓸 점검 기준 (사용자 요청 "유사 기준 추가 제시")

새 앱을 만들거나 고칠 때 `docs/app-development-guide.md`의 체크리스트에 넣기를 권합니다.

1. **설명–동작 일치**: meta description·apps.json·도움말·placeholder·토스트 문구를 코드와 대조했는가. 기능을 바꾸면 문구도 같이 바꿨는가.
2. **화면당 primary 1개, 삭제는 danger + 확인 또는 되돌리기**, 이동·다운로드에 danger 금지.
3. **상태 4종**: 불러오는 중 / 비어 있음 / 실패 / 부분 실패(N건 건너뜀)가 모두 화면에 보이는가. 실패를 성공색으로 그리지 않는가.
4. **360px·844×390·1280×720 세 크기에서 겹침·잘림 없음**, `100dvh`, 아래 고정 바와 토스트 간격, safe-area.
5. **터치 기기**: 44px 터치 영역, 입력 16px, title·hover에만 있는 설명 없음, 키보드 힌트는 `hover:none`에서 숨김, 길게 누르기·드래그 대체 수단.
6. **전자칠판 가독성**: 전체화면·발표 모드에서 글자가 화면에 비례해 커지는가, 교실 뒤에서 읽히는 대비(4.5:1 이상)인가, 정답·교사용 정보가 기본으로 숨겨져 있는가.
7. **데이터 보존**: 새로고침·뒤로 가기·공유 링크 열기로 쓰던 내용이 사라지지 않는가(임시 저장 또는 이탈 경고), 저장은 덮어쓰기인가 사본인가가 명확한가.
8. **용어 사전**: 같은 동작은 앱 전체에서 한 단어(아래 권장). 영어·개발자 용어·내부 식별자(`snake_case`)를 화면에 내지 않는다.
   - 백업/복구 → "파일로 저장 / 파일 불러오기", 기록 → "최근 기록", 초기화 → "처음부터"(확인 필수), 되돌리기(취소 아님), 화면 모드(테마 아님), 홈.
9. **학년 눈높이**: 대상 학년 교과서 표기("5분의 2"), `VUI.josa`로 조사 처리, 교과 밖 용어(상대도수·발상 기법) 풀어 쓰기.
10. **출제 검증**: 무작위 문제는 정답이 하나뿐인지, 입력 단위로 정답에 도달할 수 있는지 생성기에서 확인.
11. **첫 화면 속도**: `<head>` 동기 외부 스크립트 금지(필요 시점에 동적 로드), 아이콘은 빌드 때 인라인.
12. **권한 요청 시점**: 카메라·알림·마이크는 사용자가 해당 버튼을 누를 때만.
13. **구형 기기 문법**: lookbehind 정규식 등 iOS 16.4 미만에서 문법 오류가 나는 구문 금지(스모크 검사에 grep 추가 가능).
14. **공유 화면 대응**: 큰 화면에서 만든 결과(칠판·학습지·자리표)를 휴대폰 공유 링크로 열었을 때 잘리지 않는가.
