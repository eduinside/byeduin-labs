## 2. 작업 순서와 이유

1. **검색창**: 작고 독립적이다. 먼저 끝내 홈을 정리한다.
2. **뽑기·모둠**: 교사가 거의 매 시간 쓰는 도구다. 자리 배치(`seating`)의 명단 형식과 배치 알고리즘을 그대로 가져다 쓸 수 있어 위험이 낮다.
3. **시계 보기**: SimKit 미션 틀에 바늘 끌기 하나만 새로 만들면 된다. 저학년(1~2학년) 수학 앱이 부족하다.
4. **그래프 그리기**: 막대·꺾은선 SVG 그리기 함수를 여기서 만들어 `public/common/vgraph.js`로 둔다.
5. **태양과 그림자**: 측정 기록 그래프를 4번의 `vgraph.js`로 그린다. 천문 계산 검증이 필요해 가장 크다.

단원 시기가 맞으면 순서를 바꾼다(예: 6학년 「계절의 변화」 수업이 곧이면 5번을 앞당기고, 그래프는 막대·꺾은선만 먼저).

## 3. 공통 원칙

- **셸**: 시뮬레이션 3종은 기존 15종 관행대로 `immersive` 스타일(앱이 화면 전체를 쓰고 셸은 홈·테마·공유 버튼만 얹음) + SimKit(`missions`·`toast`·`store`·`share`·`speak`·`sound`). 화면 구성은 기존 앱과 같은 순서: 인트로 → 모드 탭(자유 탐험·미션) → 결과. 뽑기·모둠은 자리 배치처럼 목록 화면 + 전체화면 무대.
- **파일**: 마크업·스타일은 `src/pages/apps/<id>/index.astro`, 로직이 300줄을 넘으면 `public/apps/<id>/app.js`로 분리(자리 배치 방식).
- **태블릿 조작 전제**: 학생 태블릿(갤럭시탭 1280×800, 아이패드 1180×820·1024×768 가로·세로)과 전자칠판 손가락 조작이 기본이다. 마우스는 덤.
  - 터치 영역 48px 이상(작은 화면에서도 44px 밑으로 내리지 않음), 손가락에 가려지는 정보는 손가락 위쪽에 표시.
  - hover에 기대는 기능 없음(버튼·안내는 늘 보이게). 길게 누르기는 보조 수단으로만.
  - 끄는 영역은 `touch-action: none`으로 끄는 동안 화면이 스크롤·확대되지 않게 하고, 나머지 화면은 스크롤 가능하게 둔다.
  - 숫자 입력은 화면 키보드 대신 앱 안 숫자 입력판(큰 버튼)으로 받는다(화면 키보드가 시계·그래프를 가리지 않게).
  - 가로·세로 회전, 분할 화면(절반 폭)에서도 조작 대상이 화면 안에 다 들어온다. 세로 높이 700px 이하에서 스크롤 없이 핵심 조작이 보이도록.
- **조작**: Pointer Events로 터치·펜·마우스를 한 번에 처리한다. 끄는 조작에는 모두 버튼·키보드 대체 조작을 둔다. 본문 14px 이상(학생 화면 16px 이상), `prefers-reduced-motion`이면 애니메이션 생략.
- **저장**: `SimKit.store` 또는 `VUI.storage`로 읽을 때 형식 검사. 키는 `<id>:v1`(시뮬레이션), `vives-picker-v1`(뽑기·모둠).
- **공유**: 시뮬레이션은 `#share=`로 상태만 공유한다(학생 정보 없음). 뽑기·모둠은 학생 이름이 들어가므로 공유 링크를 만들지 않는다.
- **문구**: 학생 화면은 초등 눈높이 존댓말("~해 보세요"), 조사는 `SimKit.josa`/`VUI` 조사 함수.
- **외부 의존**: 없음. 글꼴·아이콘은 기존 공용 자산만 쓴다.

## 5. 앱마다 공통 절차

1. `node scripts/scaffold-app.cjs --id … --base … --category edu --subcategory … --emoji … --lucide … --desc "…"` (각 문서의 값 사용)
2. `apps.json` 보강: `badge`, `seo.title`·`seo.description`·`seo.keywords`
3. 구현 → `npm run dev`에서 확인(태블릿 1280×800·1024×768 가로와 768×1024 세로를 먼저, 그다음 375px·1920px. 터치 에뮬레이션, 라이트·다크, 키보드만으로 조작)
4. `npm run build` → `npm run smoke` 콘솔 오류 0건
5. `docs/OVERVIEW.md` 앱 표·변경 이력, `README.md` 앱 표 갱신(`/sync-docs`로 불일치 확인)
6. 커밋: 앱마다 `feat(<id>): …`

작업은 `feat/2026-10-apps` 브랜치 하나에서 항목마다 커밋을 나눠 순서대로 한다(지난 `audit-fixes`와 같은 방식). main에 푸시하면 Cloudflare가 바로 배포하므로, 덜 만든 앱이 홈에 보이지 않게 스캐폴드부터 이 브랜치에서 하고, 운영자가 확인한 뒤 main에 합친다. 미리 보기가 필요하면 `npx wrangler pages deploy dist --project-name=byeduin-labs --branch=feat-2026-10-apps`(main 이외 브랜치는 자동 빌드되지 않음).
