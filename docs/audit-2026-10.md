## 2. 배포·빌드·운영

### 2.1 [높음] GitHub Actions가 빌드되지 않은 `public/`을 운영에 배포

- 근거: `.github/workflows/deploy.yml`이 푸시마다 `wrangler pages deploy public --project-name=byeduin-labs`를 실행합니다. `astro build` 단계가 없고 Node 20을 씁니다(`package.json`은 22.12 이상 요구). 최근 실행(176회차, 2026-10-05)도 26초 만에 성공했습니다.
- `public/`에는 `index.html`과 `apps/<id>/index.html`이 없습니다(Astro 이식 이후 `dist/`에만 생김). 그런데 운영 사이트는 Astro 빌드 결과를 서빙하고 있으므로, 별도 경로(Cloudflare Pages의 Git 연동 빌드로 추정)가 뒤이어 덮어쓰고 있는 것으로 보입니다.
- 위험: 두 배포 중 나중에 끝난 쪽이 운영이 됩니다. 지금은 Actions가 먼저 끝나므로 푸시 직후 잠깐 홈과 앱 페이지가 404가 될 수 있고(추정), Actions를 수동 재실행하거나 Cloudflare 빌드가 실패한 날에는 404 상태가 유지됩니다.
- **결정(2026-10-05): GitHub Actions를 끄고 Cloudflare Pages의 Git 연동 빌드 하나만 씁니다.** 가장 손이 덜 가는 방식입니다. 푸시하면 Cloudflare가 `npm run build` 후 `dist/`와 `functions/`를 함께 배포하므로 Actions가 따로 해 줄 일이 없습니다. GitHub 시크릿(`CLOUDFLARE_API_TOKEN`)도 필요 없어집니다.
- 순서:
  1. Cloudflare 대시보드 → Pages → byeduin-labs → 배포 이력에서, 최근 푸시마다 출처가 "GitHub 연동"인 배포가 생기는지 확인합니다. 빌드 명령 `npm run build`, 출력 디렉터리 `dist`, Node 22 이상(환경 변수 `NODE_VERSION`)인지도 봅니다.
  2. 확인되면 `.github/workflows/deploy.yml`을 삭제합니다.
  3. 푸시 후 운영 사이트의 홈과 `/api/notices`가 정상인지 한 번 확인합니다.
- 1번에서 Git 연동 배포가 보이지 않으면 삭제하지 말고, 워크플로를 Node 22 → `npm ci` → `npm run build` → `wrangler pages deploy dist`로 고칩니다. 운영 사이트에 오늘 커밋의 페이지가 올라와 있고 이 PC의 `dist/`는 9월 27일 것이었으므로 Git 연동이 동작 중일 가능성이 높습니다(추정).
- 참고: 워크플로는 2026년 초 "Functions 배포를 위해" 복원된 이력이 있습니다(`0a437f4`). Git 연동 빌드는 저장소 루트의 `functions/`를 자동으로 포함하므로 지금은 그 이유가 해당하지 않습니다.

#### 단축 주소 API 설명 — "임의 URL 단축"이란

`/api/shorten`은 short.io를 쓰는 것이 맞습니다. 서버에 보관한 short.io API 키로 운영자 계정의 단축 도메인에 링크를 만들어 돌려줍니다. 문제는 short.io가 아니라 이 API가 **어떤 주소든, 누가 보내든** 받아 준다는 점입니다.

- 쓰는 곳은 두 종류입니다.
  - 자기 앱의 공유 링크 단축(9개 앱: book-share, chalkboard, embed, flash-deck, idea-lab, math-sheet, md-editor, scoring-table, signage-maker). 단축 대상이 항상 `https://eduin.info/apps/...`입니다.
  - qr 앱의 "단축 URL" 버튼(`qr/index.astro:944-956`). 사용자가 QR로 만든 **아무 주소**를 단축합니다. 이것이 "임의 URL 단축"입니다.
- 서버는 두 경우를 구분하지 않고 `body.url`이 비어 있지만 않으면 통과시킵니다(`shorten.js:13-14`). CORS도 `*`입니다.
- 그래서 생기는 일:
  - 누구든 이 API에 피싱 사이트 주소를 보내 운영자의 단축 도메인으로 된 링크를 받을 수 있습니다. 링크가 신고되면 운영자 계정·도메인이 정지될 수 있습니다.
  - short.io 계정의 링크 생성 한도를 외부에서 소진시킬 수 있습니다.

**결정(2026-10-05): 임의 URL 단축은 의도한 기능이므로 유지합니다.** 기능은 그대로 두고, eduin.info 화면을 거치지 않은 외부 호출만 줄입니다.

| 조치 | 내용 | 사용자 영향 |
|---|---|---|
| 형식 검사 | `http:`/`https:` 주소만, 길이 상한(예: 8,000자) | 없음 |
| 출처 검사 | 요청의 `Origin`/호스트가 `eduin.info`(및 localhost)일 때만 처리, CORS `*` 제거 | 없음(모든 호출이 같은 출처) |
| 횟수 상한 | Cache API 카운터로 IP당 일일 상한 + 사이트 전체 일일 상한. 학교 공용 IP를 감안해 IP당 한도는 넉넉히 | 한도 초과 시 원본 주소 복사로 대체(지금도 있는 폴백) |
| 로그 정리 | `shorten.js:26, 47`의 요청 URL 원문 로그 삭제(공유 내용이 URL에 들어 있어 로그에 남음) | 없음 |

남는 위험: 출처 검사는 브라우저 밖 스크립트가 헤더를 꾸미면 통과하므로, 실제 방어선은 횟수 상한입니다. 사이트 전체 일일 상한을 short.io 요금제의 링크 한도보다 충분히 낮게 잡아 두면, 남용이 있어도 그날 단축만 멈추고 계정 한도는 지킬 수 있습니다. short.io 대시보드에서 낯선 도메인으로 가는 링크가 생기는지 가끔 확인하세요.

### 4.2 [높음] 쌓이기만 하는 데이터

- 동기화(`_sync.js`): 아무 6자리 코드나 유효하고 코드 수·항목 수 제한이 없습니다. 칠판은 문서당 512KB, 연산연습지·마크다운은 항목당 200KB입니다. 스크립트로 D1 5GB를 채울 수 있고, 장기 미사용 행을 지우는 절차가 없습니다.
- 마당: 보드 생성에 제한이 없고, 만료된 보드는 접근만 막힐 뿐 D1·R2에 남습니다(`_madang-common.js:19`). 업로드 후 게시하지 않은 이미지는 고아 객체로 남습니다(`madang-upload.js:52-56`). 보드당 60MB × 약 170개면 R2 10GB입니다.
- 조치: `scripts/`에 "만료 후 N일 지난 보드와 그 이미지 삭제", "1년 이상 갱신 없는 동기화 행 삭제" 수동 스크립트를 두고 학기마다 실행합니다(Pages에는 cron이 없음). 보드 생성과 동기화 쓰기에 IP당 일일 상한을 둡니다.

### 4.3 [중간] 마당 폴링의 요청·읽기 소모

- 클라이언트가 2·5·8초 간격으로 폴링합니다(`madang/index.astro:567-569`). 30명 × 40분 수업이면 한산할 때 약 9천, 활발할 때 최대 약 3만 6천 요청입니다(추정). Functions 무료 한도 일 10만은 사이트의 모든 `/api`가 함께 씁니다.
- 반응(이모지) 한 번마다 보드 rev가 올라가 모든 참여자가 전체 조회(카드 최대 300 + 반응 + 댓글 집계)를 다시 합니다(`madang.js:231-245, 571`). 활발한 수업에서 D1 일 500만 행 읽기를 넘을 수 있습니다(추정).
- 조치: 최소 간격을 3~4초로, 반응은 rev를 올리지 않고 다음 주기에 합산, 반응 수를 카드 행에 저장, 연속 실패 시 간격을 늘립니다.
- 같은 날 여러 학급이 마당을 쓰는 일이 생기면 Cloudflare 대시보드에서 실제 요청 수를 한 번 확인해 두세요.

### 4.4 [중간] 그 밖의 안정성

- `madang-upload.js:29-31, 55-56`: 설정 JSON을 읽고 통째로 다시 씁니다. 교사가 잠금·PIN을 바꾸는 순간 학생 업로드가 끝나면 옛 설정으로 덮입니다. `imageBytes`를 정수 칼럼으로 분리하세요.
- 금칙어 정규식(`madang.js:47-50`, `idea-lab.js:31-39`): 글자 사이 공백을 허용해 "다시 발명", "도시 발전", "출시 발표"가 차단됩니다. 발명 앱에서는 핵심 단어와 충돌합니다. 두 파일의 목록도 서로 다릅니다.
- `_sync.js:116`: 클라이언트가 보낸 `updatedAt`을 형식 검사 없이 씁니다. 먼 미래 값이 한 번 들어가면 이후 정상 저장이 모두 무시됩니다.
- `sync.js:104-105`: 이미 데이터가 있는 기기에서 코드를 연결하면 확인 없이 서버본으로 교체됩니다.
- `sync.js:176-179`: 삭제 표식이 없어 Read Tree에서 한 기기가 읽음을 해제해도 다른 기기가 되살립니다.
- `manual.js`, `notices.js`, `yt-duration.js`: `Cache-Control`만 있고 엣지 캐시(`caches.default`)를 쓰지 않아 요청마다 함수와 D1이 실행됩니다. `notices.js`는 오류 응답도 30분 캐시됩니다.

  - 적용 방법(코드는 지우지 않고 보존):
    1. 페이지: `src/pages/apps/<id>/`를 `src/pages/apps/_<id>/`로 이름을 바꿉니다. Astro는 `_`로 시작하는 폴더를 페이지로 만들지 않으므로 해당 주소는 404가 됩니다. 다시 공개할 때는 이름만 되돌리면 됩니다.
    2. 사이트맵: `scripts/generate-sitemap.cjs`가 `hidden` 앱을 건너뛰게 고치고 `npm run sitemap`으로 다시 생성합니다.
    3. 404 안내: `public/404.html`이 `apps.json`으로 비슷한 앱을 추천하므로 `hidden` 앱은 추천에서 제외합니다.
    4. 서버 API: 페이지만 막으면 API는 계속 호출됩니다. `madang`·`madang-upload`·`madang-img`·`signage`·`signage-prompt`·`signage-image`는 요청 첫머리에서 410을 돌려주도록 막습니다(파일은 보존).

  - **적용 전에 알아둘 영향** — 막는 순간 기존 링크가 전부 끊깁니다.
    - madang: 이미 만든 보드의 초대 링크·QR이 404가 됩니다. D1의 카드와 R2의 사진은 남지만 볼 방법이 없어집니다. 진행 중인 수업이 있으면 먼저 내보내기(CSV·PDF)를 해 두어야 합니다.
    - embed: 이미 노션 등에 넣어 둔 임베드 주소가 빈 화면(404)이 됩니다.
    - shortcut: 홈 화면에 추가해 둔 바로가기 아이콘이 동작하지 않습니다.

    - bubble-chat: 서버 저장 데이터가 없어 영향이 없습니다.
  - 막고 나면 정리되는 항목: embed·shortcut·bubble-chat의 3.1 항목, 3.3·3.4 전체, 4.3(마당 폴링), 8.3의 해당 앱 행은 다시 공개할 때의 선행 조건으로만 남습니다. 마당을 계속 비공개로 둘 경우 4.2의 마당 데이터(D1·R2)는 한 번에 비울 수 있습니다.
- 워크스페이스 규칙의 `STATUS.md`, `CHANGELOG`가 이 프로젝트에는 없습니다. 변경 이력은 `OVERVIEW.md` 하단에 있습니다.
