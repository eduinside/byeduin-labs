## 1. 개요 및 v1과의 관계

| 항목 | 값 |
|------|-----|
| 앱 ID | `moon-phase-v2` (`/apps/moon-phase-v2/`) — 최종 네이밍은 배치 방침 확정 시 조정 |
| 이름 · 이모지 | 달의 위상 3D · 🌗 |
| 셸 | `immersive` (v1은 컬럼형 카드 3개 → v2는 뷰포트 소유형으로 몰입감↑) |
| 카테고리 | `edu` / `edu-sim` · 배지 `시뮬레이션` |
| 한 줄 | 달을 직접 궤도에서 돌려 위상이 왜 바뀌는지 체감하고, 일식·월식까지 알아보는 입체 시뮬레이션 |
| 교과 | 6학년 「지구와 달의 운동」(달의 위상 변화와 원인). 일식·월식은 **중등 연계 심화 모드**로 분리 표기 |

### v1이 이미 가진 것 (계승할 자산)
현재 [moon-phase](../public/apps/moon-phase/index.html)는 이미 상당히 완성도 높음 — v2는 백지 재작성이 아니라 **조작감·입체감 축의 리뉴얼**:
- 월령/음력 계산(`SYNODIC_MONTH` 기준), 날짜 애니메이션(시간 진행)
- 위상 8종별 관측 정보(방향·뜨고 지는 시각·관측 팁·초저녁 하늘) — `getMoonInfo()`의 텍스트 자산은 **그대로 이식**
- 2D 달 원반 명암 렌더(clip+ellipse), 위에서 본 궤도, 초저녁 하늘 사이드뷰
- 이미 "삭 전후 개기일식 가능" 문구 존재 → 일식·월식 심화의 자연스러운 연결점

### v2가 새로 주는 것
1. **조작감**: 슬라이더 → **궤도에서 달을 직접 드래그**해 공전(각도→위상 실시간). 하늘 사이드뷰 관측자 시점도 조절.
2. **입체감(경로 B)**: WebGL 없이 2D pseudo-3D — 명암 그라디언트 구체, 원근 기울인 타원 궤도, 지구 자전 표현.
3. **인과 연결 강화**: "궤도 위 달의 위치 ↔ 지구에서 보는 모양"을 **한 화면에서 동시 하이라이트**(v1은 카드 분리).
4. **일식·월식 심화 모드**(신규): 같은 태양-지구-달 기하 재사용.

## 2. 왜 경로 B(2D pseudo-3D)인가 — 근거

| 축 | 경로 A (Three.js CDN) | 경로 B (2D pseudo-3D) ✅ |
|----|----------------------|--------------------------|
| 입체 리얼리즘 | 높음 | 중(충분) |
| 저사양 교실기기 안정성 | WebGL 실패 fallback 필수 | 항상 동작 |
| 오프라인 | CDN 로드 의존 | 완전 독립 |
| 학습 목적 부합 | 과잉 | **정확히 부합**(모양의 원인 이해) |
| v1 렌더 자산 재사용 | 폐기 | **clip+ellipse 로직 계승 가능** |

입체감의 목적은 리얼리즘이 아니라 "위치→모양"의 인과 이해이며, 배포 대상이 초등 교실 기기임을 고려해 **경로 B 확정**. Canvas 2D 유지 + 명암/원근 셰이딩으로 입체감 확보.

## 3. 화면 흐름

```
[인트로] → [자유 탐험: 궤도 조작] → [미션: 위상 예측] → [심화: 일식·월식] → [결과 정리]
```

### 3-1. 인트로
- 미션 카드: "달을 손으로 돌려 볼까요? 왜 초승달, 보름달이 생기는지 알아봐요." + `시작하기`.

### 3-2. 자유 탐험 — 궤도 조작 (핵심 리뉴얼)
- **메인 뷰(위에서 본 3D 기울인 궤도)**: 중앙 지구, 바깥 원궤도의 달을 **드래그로 공전**. 태양광은 화면 한쪽에서 평행하게 들어오는 방향으로 고정 표시(밝은 반구/그림자 반구가 항상 보임).
- **연동 달 원반(지구 관측자 시점)**: 드래그로 달 위치가 바뀌면 관측자가 보는 위상이 실시간으로 그려짐 — **위치와 모양을 한 화면에서 동시에** 보게 함(v1의 핵심 개선).
- **입체 표현**: 달 구체는 라디얼/방향성 명암 그라디언트(터미네이터 곡선), 궤도는 y축 압축 타원 + 앞/뒤 구간 명도차로 원근.
- **정보 패널**: v1의 위상명·관측 방향·초저녁 하늘 텍스트 이식. 월령/음력 병기.
- **모드 전환**: `자유 드래그` ↔ `자동 재생`(날짜 진행, v1 애니메이션 계승) ↔ `관측자 시점`(사이드뷰 강조).

### 3-3. 미션 — 위상 예측
| # | 유형 | 예 |
|---|------|----|
| ① 위치→모양 | 궤도의 특정 위치를 제시 → 지구에서 보이는 모양 3지선다 | 태양 반대편 → 보름달 |
| ② 모양→위치 | 목표 위상(예: 상현달) 제시 → 달을 맞는 궤도 위치로 드래그 | |
| ③ 순서 | 초승→상현→보름→하현 위상 순서 배열 | |
- ②는 정규 위치 허용 오차 범위 내 스냅 판정. 예측→확인 원칙(①은 선택 후 드래그로 확인).

### 3-4. 심화 모드 — 일식·월식 (중등 연계, 성취기준 외 명시)
> UI에 `심화 · 더 알아보기` 배지로 초등 필수 아님을 표시.

- **재사용**: 같은 태양-지구-달 기하. 삭(신월) 위치에서 "특별한 날엔 달이 태양을 가려요"(일식), 망(보름) 위치에서 "지구 그림자에 달이 들어가요"(월식) 애니메이션.
- **매달 안 일어나는 이유(궤도 경사)**: 정량(5°) 대신 **정성 연출** — 달의 길이 살짝 기울어 대개 그림자를 위/아래로 비껴가고, 특별히 일직선일 때만 일어남을 기울인 궤도면으로 보여줌. "그믐마다 일식" 오개념 차단이 목표.
- **미션(선택)**: "일식이 일어나려면 달은 어디에?"(삭 위치) / "월식은 보름/그믐?"(보름).
- 판정·별점은 초등 필수 미션과 분리 집계(심화는 도전 배지).

### 3-5. 결과 / 배움 정리
- 정리 카드: "달의 모양은 **태양-지구-달의 위치 관계** 때문에 바뀌어요. 달이 지구를 도는 동안 햇빛 받는 부분이 다르게 보이는 거예요." (+ 심화 완료 시 일식·월식 한 줄 요약)
- `다시` / `자유 탐험` / 공유(현재 달 위치·위상).

## 4. 기술 설계

### 4-1. 렌더링 (경로 B)
- **Canvas 2D** 유지(v1 계승). 달 구체: 원 + 방향성 그라디언트로 명암, 터미네이터는 v1의 clip+ellipse 방식 개선(반타원 폭 = 위상). 궤도: y 압축 타원, 달 토큰은 앞/뒤 구간 크기·명도 변조로 원근.
- 드래그: 포인터 각도 → 월령(phase) 매핑. 관성 없이 즉시 반응(교육용 정확성 우선).
- **접근성 대체(재검토 보완)**: 궤도 드래그의 접근성 폴백으로 **v1의 위상 슬라이더를 보조 컨트롤로 유지** — 드래그와 슬라이더가 같은 `phaseAngle`을 양방향 동기화. 드래그 불가·키보드 사용자도 슬라이더로 전 위상 도달 가능(드래그-heavy 앱 공통 원칙과 달리, 여기선 단일 객체라 슬라이더로 완전 대체됨).
- 성능: requestAnimationFrame 단일 루프, 오프스크린 버퍼로 달 표면 패턴 캐시(v1의 `moonSurfacePattern` 계승).

### 4-2. 상태 모델
```
state = {
  phaseAngle,           // 궤도상 달 위치(rad) → 위상 파생
  mode: 'drag' | 'auto' | 'observer',
  simDate,              // 자동 재생용(v1 계승)
  eclipse: { active, type: 'solar'|'lunar'|null },
  progress: { missions:{...}, advanced:{...} }
}
```

### 4-3. 저장 · 공유
- `localStorage` 키: `moon-phase-v2:v1` → `{ missions, advanced, lastAngle, settings }`.
- 공유: `#share=` payload `{ v: 1, phaseAngle }` — 현재 달 위치/위상 공유. `shareCurrentPage()` 단축링크.

### 4-4. 의존성
- 외부 CDN 0(경로 B 확정 근거). 오프라인 완전 동작. WebGL 미사용 → fallback 불필요.

## 5. 디자인

- 공통 3종 + 표준 스크립트, `immersive` 셸.
- v1의 밤하늘 배경 밝기 연동(위상↔배경 hsl) 아이디어 계승. 팔레트: `--mp-sun`(햇빛 방향), `--mp-lit`(밝은 반구), `--mp-dark`(그림자), `--mp-orbit`.
- 드래그 핸들(달)은 터치 타깃 ≥ 44px, 잡을 수 있음을 나타내는 시각 힌트.
- 다크모드 기본 친화(밤하늘 테마) — 라이트모드에서도 궤도·명암 대비 확인.

## 6. 스코프 제한 (Non-goals)

- **WebGL/3D 엔진 없음**(경로 B 확정). 실사 텍스처·레이트레이싱 없음.
- 조석·칭동·궤도 이심률 등 고급 천문 없음.
- 일식·월식의 정량(경사각·사로스 주기) 없음 — 정성 연출만.
- v1을 수정하지 않음(공존). v1 삭제·리다이렉트 여부는 산출물 비교 후 별도 결정.

## 7. 제작·배포 절차

1. 스캐폴드:
   ```bash
   node scripts/scaffold-app.js --id moon-phase-v2 --name "달의 위상 3D" --base immersive \
     --category edu --subcategory edu-sim --emoji 🌗 --desc "달을 직접 돌려 위상을 이해하고 일식·월식까지"
   ```
2. `apps.json` 수동 보강: `badge: "시뮬레이션"`, SEO:
   - `seo.title`: `달의 위상 3D — 달을 돌려 보는 입체 시뮬레이션`
   - `seo.description`: `달을 궤도에서 직접 돌리며 초승달·보름달이 생기는 이유를 알아보세요. 일식·월식 심화까지, 초등 6학년 지구와 달의 운동을 입체로 체험하는 무료 시뮬레이션.`
   - `seo.keywords`: `달의 위상`, `달의 위상 변화`, `지구와 달의 운동`, `일식 월식`, `과학 6학년`, `천체 시뮬레이션`
3. 구현 → `npm run dev` → 검증 → `npm run inject` → `npm run og` → `npm run sitemap` → 커밋.
4. **배치 결정 게이트**: v1·v2 나란히 두고 조작감·정확성·기기 안정성 비교 → 홈 목록에서 v1 유지/강등/리다이렉트 최종 결정.

## 8. 검수 체크리스트

- [ ] 궤도상 달 위치와 지구 관측 위상이 물리적으로 정확히 대응하는가 (삭=관측불가, 망=보름, 태양 반대편)
- [ ] 드래그가 태블릿 터치에서 매끄럽고 각도→위상 매핑이 정확한가
- [ ] v1의 위상별 관측 정보 텍스트가 손실 없이 이식되었는가
- [ ] 명암 터미네이터가 8위상 모두에서 자연스러운가 (경로 B 입체감 검증)
- [ ] 일식·월식 심화가 "성취기준 외 심화"로 명확히 표시되고, 초등 필수 미션과 분리 집계되는가
- [ ] 궤도 경사 정성 연출로 "매달 일식/월식" 오개념이 차단되는가
- [ ] WebGL 미사용으로 저사양 기기에서 fallback 없이 동작하는가
- [ ] 다크/라이트 대비·포커스 링·공유 복원 정상
- [ ] inject/og/sitemap 산출물 정상 (개발 가이드 §7 공통 체크 포함)
